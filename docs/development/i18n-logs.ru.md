# Язык логов и ошибок (R234)

Язык, на котором балансер, cppworker и агент пишут логи и отвечают ошибками, задаётся
**на стенде**, а не в браузере. Язык интерфейса WebUI (`langSelect`) на логи не влияет:
это две разные настройки, и путать их — самая частая причина вопроса «переключил язык,
а в логах всё по-русски».

## Что считается «локализованным»

| Что | Где | Как меняется |
|---|---|---|
| Логи Go-процессов (балансер, cppworker, agent) | stderr/stdout контейнеров, live-логи WebUI | настройка языка стенда |
| Ошибки REST API (`{"error": ...}`) | ответы `/api/*` | настройка языка стенда |
| Тексты интерфейса WebUI | страницы панели | переключатель языка в шапке (localStorage) |
| Имена переменных, команды, пути, HTTP-коды | везде | **не переводятся** |
| Строки, которые печатает сам код как факт (WARN/ERROR из llama.cpp, вывод `rpc-server`) | логи | остаются как есть — их ищут grep'ом |

## Приоритет источников

```
flag -log-lang  >  OLLAMALEGION_LOG_LANG / LB_LOG_LANG  >  config.json logging.language
                >  LANG / LC_ALL  >  ru
```

У воркеров первый шаг заменён на `<КОМПОНЕНТ>_LOG_LANG` (например `CPPWORKER_LOG_LANG`),
чтобы можно было разово переопределить язык одного контейнера.

Значения: `ru`, `en`, `auto` (`auto` = взять из локали контейнера, при неясности — `ru`).

## Источник истины — балансер

Балансер выставляет язык и раздаёт его воркерам:

```
GET /api/v1/i18n
  -> {"language":"ru|en","resolved":"ru|en","supported":["ru","en"],
      "source":"env|config|locale"}

PUT /api/v1/i18n          (только администратор)
  <- {"language":"ru|en|auto"}
  -> {"success":true,"language":"en","message":"..."}
```

* `language` в GET — **настройка** (может быть `auto`), `resolved` — **действующий язык**,
  на котором реально пишутся сообщения.
* `PUT` применяет язык немедленно (`i18n.Set`) и сохраняет его в `logging.language`
  конфига; `auto` сохраняется как `auto`, чтобы следующий старт снова смотрел на локаль.
* Тот же выбор доступен через `GET/PUT /api/v1/cluster/config` (поле `logLanguage`) —
  страница настроек WebUI пользуется именно им при сохранении формы.

Воркеры (`cppworker`, `agent`) раз в `OLLAMALEGION_LOG_LANG_SYNC_SEC` (по умолчанию 60 с)
спрашивают `GET /api/v1/i18n` и применяют язык. Поэтому смена языка в WebUI действует на
весь стенд **без перезапуска контейнеров**. Если балансер недоступен, воркер остаётся на
локальной настройке (язык не «сбрасывается» из-за сетевого сбоя) и пишет об этом одну
строку, а не по строке в минуту.

## Как включить

**Через env** (стартовое значение, приоритет выше конфига):

```dotenv
# deployments/.env
OLLAMALEGION_LOG_LANG=en          # ru | en | auto
# точечно для одного контейнера:
CPPWORKER_LOG_LANG=ru
AGENT_LOG_LANG=en
OLLAMALEGION_LOG_LANG_SYNC_SEC=60 # как часто воркеры спрашивают балансер
```

**Через WebUI**: «Настройки» → секция «Язык логов и ошибок» → выбрать язык → «Применить».
Доступно администратору; гость видит настройку, но кнопка неактивна и статус объясняет почему.

**Через API**:

```bash
curl -s -X PUT http://localhost:18081/api/v1/i18n \
  -H "X-API-Token: $CPPWORKER_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"language":"en"}'
```

## Как добавить сообщение

1. Ключ и оба текста — в `internal/i18n/messages.go`:
   `"api.i18n.unsaved": {RU: "...", EN: "..."}`.
   Глаголы `%s/%d/%v` в `ru` и `en` обязаны совпадать — это проверяет `TestCatalogVerbParity`.
2. В коде — `i18n.T("ключ", args...)` (или `i18n.Logf("ключ", args...)` для лога).
3. Ключ не переименовывать: по нему считается остаток непереведённых мест
   (`scripts/i18n-scan.py`) и он же попадает в этот документ.

## Что уже переведено, а что нет

Каталог наполняется по мере правок и **не является полным**: в коде остаются русские
лог-строки, которые ещё не вынесены в каталог. Их количество считает и печатает

```bash
python scripts/i18n-scan.py           # сводка + бюджет
python scripts/i18n-scan.py --list    # файлы и число мест, без деталей
```

Скрипт — «храповик»: бюджет (`scripts/i18n-budget.json`) можно только уменьшать. Это
честнее, чем объявить «всё локализовано», когда часть строк ещё жёстко русская.

## Проверки

| Проверка | Что гарантирует |
|---|---|
| `go test ./internal/i18n/` | разбор значений, приоритет env/локали, фолбэк, паритет глаголов, потокобезопасность, синхронизация с балансером |
| `go test ./internal/api/ -run TestI18n` | контракт GET/PUT: админ-право, отказ на мусор, `auto`, сохранение в конфиг |
| `node webui/js/modules/i18n-logs.test.js` | веб-переключатель: чтение, применение, 403, недоступный балансер |
| `internal/api` `TestI18nKeyParity_EN_RU` | в `webui/js/i18n/{ru,en}.js` нет ключей только на одном языке |
| `scripts/i18n-scan.py` | остаток непереведённых лог-строк не растёт |

## Ограничения

- Смена языка **не переписывает историю**: записи, уже попавшие в лог, остаются на прежнем
  языке. Переключение действует на новые сообщения (и на ответы API с этого момента).
- Язык балансера и воркеров сходится за один интервал синхронизации (по умолчанию ≤ 60 с),
  если менять его не через балансер, а локально в контейнере.
- Сообщения, которых нет в каталоге, печатаются как раньше (исходный русский текст).
