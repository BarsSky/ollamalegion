# Fix: 503 "model not loaded and auto-loaded" при num_ctx > default (gemma-4, qwen3.x)

## Symptom
OpenWebUI/Cline -> HTTP 503 "model not loaded and auto-loaded" при num_ctx > 32K (65536, 128000).

## Root cause (3 bugs)
1. cppworker EstimateKVCacheBytes returns 0 for gemma-4/qwen3 (GGUF v3 parser `internal/cppbackend/backend.go:ggufKeyMap` + `ggufModelArchs` does NOT know arch -> nKvHeads=0 -> KV=0).
2. C-bridge real KV math: gemma-4 (n_layers=42 n_embd=2560 n_heads=8 n_kv_heads=2 head_dim=320), qwen3.6-35B (n_layers=40 n_embd=2048 n_heads=16 n_kv_heads=2 head_dim=128) -> rejects "VRAM insufficient".
3. tryRamFallbackReload does NOT propagate KVCacheType=q4_0 in cascade.

## Fixes (2026-07-06, verified)
1. `internal/cppbackend/backend.go` - ggufModelArchs += gemma4/gemma3/qwen3/qwen3moe/qwen3next/qwen35/qwen35moe
2. `cmd/cppworker/auto_offload.go:estimateKVCacheBytes` - nKvHeads=0 -> nHeads/4 (min 1)
3. `cmd/cppworker/inference.go:tryRamFallbackReload` - opts.KVCacheType = "q4_0"

## Build
.\scripts\build-containers.ps1 -CppWorker -CudaArch "86" (~20-30min CUDA, ~3.87GB)
docker compose -f deployments/docker-compose.cppworker-bundled-with-agent.yml up -d --no-deps --force-recreate cppworker-gpu

## Confirmed
- qwen3.6-35B chat num_ctx=32768 kv=q4_0: 200 OK in 3.3s
- gemma-4 chat num_ctx=65536: 400 with "max_vram_n_ctx=20080" (actionable, no 503)
- qwen3.6-35B pre-load: arch=qwen35moe, gpu=8, ctx=32768, kv=q4_0 -- all parameters applied

## Known limits
- nKVH=0 in /api/models for gemma-4 (gguf v3 lacks KV meta). Fix: add fields to C-bridge GetMetadata()
- Auto-reload at chat time still does not trigger cascade. Workaround: pre-load via /api/models/load-with-params
