# Таблица зависимостей функций от агента OllamaLegion

## Легенда
- ❌ **Не требуется** — функция работает без установленного агента на бэкенде
- ✅ **Требуется** — функция требует агента для корректной работы

---

## Таблица вариантов использования

| # | Вариант использования | Агент | Комментарий |
|---|----------------------|-------|-------------|
| 1 | **HTTP-проксирование запросов** (`/api/generate`, `/api/chat`, `/api/embed`) | ❌ Нет | Балансер просто перенаправляет HTTP-запрос на выбранный бэкенд. Агент не участвует в передаче трафика. |
| 2 | **Round-Robin балансировка** | ❌ Нет | Циклический выбор бэкенда по счётчику `roundRobin`, не требует метрик. |
| 3 | **Health Check бэкендов** | ❌ Нет | Проверяет `/api/tags` на Ollama напрямую, агент не используется. |
| 4 | **Session Stickiness** | ❌ Нет | Привязка сессии к бэкенду хранится в памяти балансера (`SessionManager`). |
| 5 | **Queue / Backpressure** | ❌ Нет | Очередь запросов работает на счётчиках активных запросов прокси, без метрик агента. |
| 6 | **Retry / Failover** | ❌ Нет | При ошибке бэкенда пробует другой healthy бэкенд из списка. |
| 7 | **Least-Connections балансировка** | ❌ Нет | Выбор по минимальному `ActiveReqs` (счётчик прокси), метрики агента не нужны. |
| 8 | **Базовый скоринг (`calculateScoreSimple`)** | ❌ Нет | Упрощённая формула: без бонусов за модели, penalty за ошибки и прогнозов. |
| 9 | **Model Affinity** | ✅ Да | Требует знать `RunningModels` — список загруженных моделей приходит от агента. Без агента affinity не работает (модель считается не загруженной нигде). |
| 10 | **Resource-aware scoring v2** | ✅ Да | Полная формула требует GPU/VRAM/CPU/RAM метрики от агента (`calculateScore` с `useEnhancedScoring=true`). |
| 11 | **Prewarm Controller** | ✅ Да | Для выбора free-бэкенда с наибольшим свободным VRAM нужны метрики агента. |
| 12 | **Auto-pull (Pull-on-Demand)** | ✅ Да | Проверяет наличие модели через `RunningModels` из метрик агента. |
| 13 | **Headroom Reservation** | ✅ Да | Блокировка бэкенда при превышении VRAM usage > threshold требует метрик GPU. |
| 14 | **Predictor** | ✅ Да | Прогнозирование критического состояния строится на истории метрик агента. |
| 15 | **Model Replication** | ✅ Да | Требует расширенных метрик для репликации моделей на N бэкендов. |
| 16 | **Virtual Model Router** | ✅ Да | Требует метрик для pipeline slicing и координации. |
| 17 | **Distributed Inference** | ✅ Да | Требует worker-метрик и gRPC координации. |
| 18 | **Agent Registration API** | ✅ Да | Endpoint `/api/v1/agents/register` предназначен для агентов. |
| 19 | **Agent Metrics API** | ✅ Да | Endpoint `/api/v1/agents/metrics` принимает метрики от агента. |
| 20 | **Agent Heartbeat API** | ✅ Да | Endpoint `/api/v1/agents/heartbeat` обрабатывает heartbeat агента. |
| 21 | **GPU/VRAM метрики в мониторе** | ✅ Да | GPU%, VRAM%, температура — всё приходит от агента. |
| 22 | **Unload Scheduler** | ⚠️ Частично | Может работать по таймауту без агента, но для smart eviction нужны метрики. |
| 23 | **Adaptive Weight Tuner** | ✅ Да | Требует истории latency/success метрик для адаптации весов. |

## Режимы работы без агента

### Рекомендуемый минимальный конфиг (без агента)

```json
{
  "balancing": {
    "algorithm": "roundrobin",
    "modelAffinity": false,
    "sessionStickiness": true,
    "useEnhancedScoring": false,
    "prewarm": { "enabled": false },
    "autoPull": { "enabled": false },
    "syncModelLoad": { "enabled": false }
  }
}
```

### Что работает в минимальном режиме

- Проксирование всех Ollama API endpoints
- Round-robin / least-connections балансировка
- Session stickiness
- Queue с backpressure
- Retry на другой бэкенд при ошибке
- Health check через `/api/tags`

### Что НЕ работает в минимальном режиме

- Model affinity (модель загружается заново на каждый бэкенд)
- Расширенный скоринг (все бэкенды считаются равными по ресурсам)
- Предварительная загрузка моделей
- Автоматический pull моделей
- GPU/VRAM мониторинг
- Прогнозирование нагрузки
- Smart unload/eviction

---

## Вывод

Для **простого проксирования** с базовой балансировкой агент **не требуется**.
Для **продвинутых функций** (affinity, resource-aware scoring, prewarm, auto-pull) агент **обязателен**.
