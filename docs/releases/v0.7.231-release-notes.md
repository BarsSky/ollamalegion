# v0.7.231 — R247: clients and agents that did not work before (RU mirror: v0.7.231-release-notes.ru.md)

> Date: 2026-10-26. Based on R246 (tools reach the model for gemma-4/DSH) and on the
> answer to "what about other client agents": the classes of clients that did NOT
> work are now closed by the plan `docs/plans/2026-10-26-clients-agents-contract-r247.md`.

## What did not work

| Client class | Before |
|---|---|
| Anthropic-native (Claude Code, `anthropic` SDK) | `POST /v1/messages` -> 404, the client was useless |
| Codex-style / Responses API | `POST /v1/responses` -> 404 |
| Structured output (`strict:true`) | accepted, but the schema was never checked |
| Weak models under hard schemas | invalid arguments went to the client -> tool error, wasted agent turn |
| Multimodal clients | images were **silently** dropped: 200, as if the model saw the picture |

## What changed

**Stage A/F — strict validation and generation retry.**
`tool_schema_validate_r247.go`: arguments are validated against the declared JSON
schema (`type` including `integer`/`number` and type arrays, `required`, `enum`,
`const`, `items`, `properties`, `additionalProperties`, `anyOf/oneOf`). Only
`strict:true` tools are checked (from `tools[].function.strict` or from the schema
itself). On violations the generation is retried once; on `/v1` the retry carries a
**nudge** (the violation list in the system message), on `/api/chat` the same prompt
is reused. Kill-switch: `CPPWORKER_STRICT_ARGS_RETRY=0`.

**Stage B — Anthropic Messages API.**
`POST /v1/messages` and `/v1/messages/count_tokens`. Translation both ways on top of
our own `/v1/chat/completions` (self-proxy), so an Anthropic client inherits the
whole working layer: argument repair, strict, tool history per model template,
retries, admission, sessions. Content blocks `text/image/tool_use/tool_result`,
`input_schema` -> `parameters`, `tool_choice` auto/any/tool; response blocks
`text`/`tool_use` (`input` is an object), `stop_reason`, `usage`; Anthropic SSE order
(`message_start` ... `input_json_delta` ... `message_stop`); Anthropic error shapes.
`count_tokens` returns a conservative estimate instead of 404.

**Stage C — OpenAI Responses API.**
`POST /v1/responses` in the same way. `input` as a string or items (`message`,
`function_call`, `function_call_output`), `instructions` -> system, flat `tools[]`
(+`strict`), `max_output_tokens`; response `{object:"response", output[],
output_text, usage}` with `message`/`function_call` items; events
`response.created` ... `response.completed` with `sequence_number`.
`previous_response_id` is an honest 400.

**Stage D — vision without silent lies.**
Image parts (`image_url`, Anthropic `image`, Responses `input_image`) are no longer
dropped silently: HTTP 415 plus `X-Vision-Supported: false`, `X-Vision-Parts: N`,
`error.code = vision_not_supported`. The check runs BEFORE normalization. mmproj
wiring remains a separate project; the refusal contract is locked by tests.

**Stage E — client expectation harness.**
`scripts/webui-e2e/client-expectations-r247.js` declares what each client considers a
correct answer (fields/types, ordering and terminators, forbidden content, and a
second turn with the tool result): Cline, Roo, DSH, OpenWebUI (x2),
Continue/LangChain strict, forced tool_choice, legacy functions, Anthropic (x2),
Responses (x2), vision-honest, strict-loop.

## Known limits

- Anthropic `input_tokens` in `message_start` is sent as `0` (usage arrives in
  `message_delta`); `thinking` blocks with `signature` and `cache_control` are not
  translated.
- Vision: honest refusal; images are not passed into the model (mmproj path needed).
- `previous_response_id` is not supported (no dialog state is stored).
- Tool-call quality remains a property of the model; the layer guarantees shape,
  argument repair and retry, not the model's "intelligence".
