# R115 — полный RPC-режим: план и принятые решения (2026-10-13)

Продолжение разбора живого падения раскладки на двух машинах
(`192.0.2.20` мастер + `192.0.2.10` CYBORG донор).

## Что установлено живыми прогонами (не гипотезы)

1. **Падение мастера — это `RPC_STATUS_ASSERT`**, а не память и не KV-гейт:

   ```
   ggml-rpc.cpp:496 / :823: Remote RPC server crashed or returned malformed response
   SIGABRT: abort (signal arrived during cgo execution)
   ```

   Макрос (`ggml-rpc.cpp:30`) вызывается, когда узел вернул ответ, который клиент
   не смог разобрать, либо соединение оборвалось. Донор при этом **жив**, ошибок
   не пишет, `RestartCount=0`.

2. **Причина — архитектура CUDA, а не только коммит.** Машинные коды:

   | бинарник | `sm_86` | `sm_120` |
   |---|---|---|
   | мастер `rpc86-r115a` (RTX 3070) | 141 | **0** |
   | донор `gpu-rpc120` (RTX 5060 Laptop) | 0 | 7 |

   Мастер собран с `CUDA_ARCH=86` (см. `deployments/.env`), донор — под свой
   `sm_120`. Копирование бинарника мастера на донора (проверено вживую) не
   лечит: загрузка заходит дальше (`offloaded 16/66`, `CUDA0 2116 MiB`,
   `RPC0 2246 MiB`), но падает там же, потому что на `sm_120` нет ни одного
   ядра. Бинарник донора восстановлен из образа `gpu-rpc120`.

3. **Фоновое дозванивание не при чём.** Замер: `rpcDeviceSnapshot` открывает
   соединения парами каждые ~30 с (кэш), а не каждые 2 с. Ручной прогон
   `scripts/rpc-shard-load.ps1` падает так же, как авто-путь (`restarts=4`).

4. **Дефолт `CUDA_ARCH=all` в `Dockerfile.gpu` НЕ содержит `120`**
   (`50;61;70;75;80;86;89;90`), а дефолт `CUDA_VERSION=12.2.0` не знает
   `sm_120` вовсе. Драйвер на обеих машинах — 617.42.

## Правило (заменяет копирование бинарников)

Узел раскладки допускается, только если совпали:

* **коммит llama.cpp** (`CPPWORKER_LLAMA_BUILD`) — иначе протокол расходится;
* **архитектура CUDA** — узел должен иметь в бинарнике ядра под СВОЮ карту.

Практически: **один образ** из сабмодуля с `CUDA_ARCH=86;120` и
`CUDA_VERSION=12.8.0`, запускаемый и на мастере, и на доноре
(`deployments/docker-compose.rpc-node.yml` берёт тот же
`CPPWORKER_GPU_TAG`, поэтому донор автоматически получает тот же коммит и,
главное, начинает нести `CPPWORKER_LLAMA_BUILD`, которого в `gpu-rpc120` нет).

## Шаги

- [x] `deployments/.env`: `CUDA_ARCH=86;120`, `CUDA_VERSION=12.8.0`.
- [x] `docker-compose.stack.yml`: build-arg `CUDA_VERSION` (дефолт 12.2.0).
- [ ] Собрать `gpu-rpc86-r115b`, проверить наличие обоих наборов ядер
      (`grep -a -c sm_120` и `sm_86` в `/app/rpc-server`).
- [ ] Развернуть тот же образ на доноре (как узел раскладки) и на мастере;
      повторить раскладку 27B (явную и авто), зафиксировать TTFT/tok-s.
- [x] **Отключение RPC флагом (R115).** Найдена причина, почему флаг не работал:
      `main.go` безусловно ставил `RPCEnabled = true` при непустом
      `CPPWORKER_RPC_SERVERS`, поэтому `CPPWORKER_RPC_ENABLE=false` перетирался.
      Разбор вынесен в чистую функцию `resolveRPCMode`
      (`cmd/cppworker/rpc_mode_r115.go`): явный флаг решающий, при `false` список
      узлов очищается. Узлы теперь отдаются потребителям только через
      `activeRPCServers()` (`internal/cppbackend/rpc_mode_r115.go`), поэтому при
      выключенном режиме нет ни dial'ов, ни ёмкости узлов в бюджете, ни сторожевых
      проверок. Тесты: `cmd/cppworker/rpc_mode_r115_test.go`,
      `internal/cppbackend/rpc_mode_r115_test.go`.
- [x] **Видимость раскладки в отчёте (R115).** `available_vram_mb` в `/api/models`
      — это ИТОГ (memfit считает локальная карта + узлы, проверено в
      `CalculateResourceLimits`), поэтому «8 ГБ» и «8 ГБ + 7 ГБ донора» были
      неразличимы. Добавлен `LayoutBreakdown` и поля `rpc_enabled`,
      `rpc_servers_active`, `vram_local_*`, `vram_remote_*`, `vram_layout_*`,
      `vram_remote_nodes`. Смысл прежних полей не изменён.
- [x] **Проверка масштабируемости (>2 машин), по коду.** `parseRPCServersR101`
      допускает до 16 узлов, Go-планировщик читает до 32 устройств
      (`maxPlanningDevices`), `CalculateTensorSplitWithRPC` делит пропорции по
      ВСЕМ устройствам (локальные + удалённые), а не по двум. Жёстких допущений
      «ровно две машины» не найдено; живая проверка N>1 узлов — после сборки.
- [ ] Проверка версии/архитектуры узла перед использованием: узел без
      подтверждённого коммита/архитектуры **не допускается** в раскладку (сейчас —
      молчаливое `version_unknown`), отказ с внятным кодом вместо `abort`.
- [ ] WebUI: интерфейс настройки RPC (список узлов, вкл/выкл, ожидаемый
      коммит, статус каждого узла, режим раскладки).
- [ ] Балансер: учесть новые поля раскладки при выборе бэкенда (ёмкость
      «локально + узлы» уже приходит в `available_vram_mb`, нужно проверить выбор
      на живом стенде с включённой раскладкой).
