## 2. Диагностика в прокси-логах

`ProxyLogEntry` получил `requestID` и `stage` (R476/R477 уже умеют и то, и
другое, но в таблицу прокси-логов эти поля не попадали). Теперь запись в
«Прокси-логах» связывается с логами балансера/воркера по `request_id`, а
колонка «Стадия» показывает, где ход завершился или умер
(`select_backend` / `admission` / `preflight` / `upstream` / `stream` /
`client_write`).

## 3. Проверено

- Go: `internal/api` (путь users.json по умолчанию, `path`+`hint` в ошибке
  сохранения, поля в TXT/JSON-экспорте), `pkg/logger` (поля отдельной картой,
  без JSON-суффикса), `internal/balancer` (контракт `requestID`/`stage` в
  `/api/v1/proxy/logs`). Полный `./internal/balancer/` — 168 с, зелёный.
- WebUI: `npm run test:webui` — все наборы зелёные, новый
  `logs-rework-r481.test.js` (14 проверок: разметка, рендер, i18n, CSS, compose);
  `i18n-placeholders.test.js` и IIFE-guard (`check_iife_exports.py`) — зелёные.
- Живьём (стенд, образы `r261110-1346`):
  - `GET /api/v1/proxy/logs?limit=3` → у записей есть `requestID` (`req…`) и
    `stage` (`upstream`, `select_backend`);
  - `GET /api/v1/logs/export?format=json` → `fields` объектом (например,
    `request_id`, `stage`, `backend`), `message` без JSON-суффикса;
    `format=txt` → поля парами `key=value` после сообщения;
  - `PUT /api/v1/auth/users` → 200, пользователь записан в
    `/app/data/users.json`; `DELETE` → 200, файл снова содержит только
    `skyadmin` (тестовый пользователь убран);
  - WebUI-разметка содержит `#logsSearch`, `#logsDownloadBundle`,
    `#logsOpenDiagnostics`, `#exportProxyLogs`, ярлык `.sidebar-diag-link`.

**Не проверено:** визуальный клик в браузере (страницы проверены разметкой и
статическими тестами; headless-браузера на стенде нет). Прокрутка sidebar на
конкретных высотах окна.
