# R368. `/api/generate` изредка отдавал `***` — исправлено шаблоном модели

Дата: 2026-10-31 — 2026-11-01. Стенд: `cppworker-gpu`, RTX 3070 (8 ГБ),
модель `gemma-4-E4B-it-Q4_K_M`, ctx 32768 / KV q4_0 / reasoning on / 42 слоя на
GPU.

**Статус: исправлено** (коммит `b7176858`), живая приёмка ниже.

## 1. Симптом

```
POST http://127.0.0.1:18080/api/generate
{"model":"gemma-4-E4B-it-Q4_K_M",
 "prompt":"Write a short paragraph about why tests matter in software engineering.",
 "stream":false,"options":{"num_predict":120}}

→ {"response":"***","done":true,"tokens":3,"durationMs":146,
   "prompt_eval_count":13,"tokensPerSec":20.45}
```

Три токена `***` и EOS за 146 мс — не деградация скорости и не обрыв
транспорта, а именно такой ответ модели.

## 2. Замеры ДО (одинаковый промпт и `num_predict=120`)

| путь | коротких ответов |
| --- | --- |
| прямой воркер `:18092/api/generate` | 1 из 12 |
| через балансер `:18080/api/generate` | 3 из 12 |
| `:18092/api/chat` (чат-шаблон применяется) | **0 из 8** |
| `/v1/completions` с явным `temperature: 0.8` | 0 из 8 |
| `/api/generate` с явным `temperature: 1.0` | 1 из 8 |

Диагноз: `/api/generate` отправлял в llama.cpp «сырой» prompt — ни шаблона
модели, ни служебных токенов начала реплики. Настоящая Ollama для
`/api/generate` шаблон ПРИМЕНЯЕТ (и только `raw:true` отключает это), а
instruction-tuned модель на сыром продолжении иногда завершается вырожденно.
`***` — не сбой, а её «сырое» начало ответа; в удачных прогонах после него шёл
нормальный абзац (видно на `raw:true` после правки: `***\n\nHere is the
paragraph: …`).

Температура влияет на частоту, но причиной не является: дефолт воркера 0.7, и
обрывы воспроизводились при нём.

## 3. Что сделано

`cmd/cppworker/generate_chat_template_r368.go`: prompt для `/api/generate`
собирается шаблоном модели ПОСЛЕ её загрузки (system → user, с
`enable_thinking` из конфига). Если шаблона нет или он «сломан»
(`chat_template_guard.go`) — прежнее поведение: system и текстовая инструкция
рассуждений подмешиваются в prompt. `raw:true` отключает и шаблон, и
подмешивание.

Порядок важен: подмешивание system/инструкции переехало из
`normalizeGenerateRequest` в fallback-функцию. Иначе у модели с шаблоном
инструкция оказалась бы в промпте дважды. Это закреплено стюард-тестом
(«normalize не присваивает Prompt»), как и обязанность `runGenerateCore` звать
сборщик.

`/v1/completions` (OpenAI-совместимый) намеренно не тронут: это completion-
эндпоинт, его клиенты рассчитывают на свои токены.

## 4. Замеры ПОСЛЕ (образ `gpu-b7176858`)

Один прогон:

```
tokens=115  tokensPerSec=31.16  prompt_eval_count=21 (было 13)  response=644 символа
```

`prompt_eval_count` вырос ровно на служебные токены шаблона — это видимое
подтверждение, что шаблон применился.

Серия из 12 прогонов на каждом пути:

| путь | коротких | пустых |
| --- | --- | --- |
| прямой воркер `:18092/api/generate` | **0 из 12** | 0 |
| через балансер `:18080/api/generate` | **0 из 12** | 0 |

`raw:true` работает как escape hatch: `prompt_eval_count=13` (шаблона нет),
ответ начинается с `***`, как и раньше.

`/api/chat` через балансер отвечает штатно (проверено до и после).

## 5. Что не проверено / ограничения

- **Проверена одна модель.** Второй файл на стенде (`Qwen3.8-27B-UD-Q4_K_M`,
  16.4 ГБ) на 8 ГБ VRAM не поднимается без частичного offload, поэтому живой
  приёмки на нём не делалось. Для моделей без шаблона поведение не меняется
  (ветка fallback), но это подтверждено тестами, а не живым прогоном.
- **`prompt_eval_count` вырос** (13 → 21 на этом промпте). Клиенты, которые
  сами считают окно по длине промпта, увидят рост — это ожидаемая цена
  ollama-совместимости.
- **Клиенты, которым нужен именно сырой prompt** (продолжение текста,
  собственные служебные токены), должны слать `raw:true`. Это поведение
  Ollama, но для существующих скриптов это изменение: без `raw` они получат
  шаблон.
- **Кэш профилей на воркере** по-прежнему обновляется раз в 5 минут (pull-sync);
  в приёмке использовался перезапуск воркера. К R368 отношения не имеет, но
  записано как известное.
