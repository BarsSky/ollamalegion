## 1. What went into the release

### WebUI: login and roles
- Dynamic upstream of the panel (`resolver 127.0.0.11`) — after `up -d` the panel
  no longer returns 503 because of a stale balancer IP.
- The `users.json` path is explained and visible (`/app/data/users.json` on the
  `balancer_data` volume); an error writing the file when creating an administrator is no longer
  swallowed — a WARN with a hint.
- The doctor `scripts/diagnose-webui-auth.ps1` (read-only) and
  [docs/features/webui-auth.md](../features/webui-auth.md) with an analysis of six typical causes.

### Profiles, lazy loading, cancellation
- Lazy loading applies the model profile (the window from the profile, not the env default),
  including the "profile cache is empty" scenario.
- Cancellation of generation by the client (`POST /api/cancel`) reaches from the balancer to the worker
  (scoped by model), the stop time is tens of milliseconds; on an empty cancellation
  layout diagnostics are printed (port 50052, `/api/rpc-peers`).
- An unavailable donor for the duration of work with the model is **excluded**, and does not crash
  the load: a TCP filter at load time, `rpc_excluded` in `/api/models`, the snapshot
  is invalidated by the composition of nodes.

### AutoTune (R230): correct memory and verifiable recommendations
- Units: metric MB are no longer passed as bytes (it used to be "0 GB free").
- Reload budget: `free + occupancy` of this model (a reload unloads it).
- `n_kv_heads`/`head_dim` are obtained from `/api/show`; without them the layout does not change.
- KV is chosen by the actual `n_ctx`; layers — by the number that really fits;
  `-2` is no longer recommended, reducing layers is forbidden.
- Applying the plan is verified against the fact: "success" without a change of configuration
  is impossible; on an error — an honest failure and a cool-down.
- Table tests on **144 configurations** (VRAM 8/16/24/32 GiB × RAM 16/32/64/120 GiB
  × 3 models × 3 contexts) + a live A10 scenario (24 GB, `ctx=131072`, KV q8_0).
  Live check — `scripts/verify-autotune-r230.ps1`.

### Stream for Cline (R231): no duplicates, no markers, a single `[DONE]`
- Reasoning is no longer copied into `content` in the stream (`FinalizeForStream`);
  an unclosed block gives an honest `finish_reason=length`, and not `stop` with empty content.
- `</think>`, `<|channel>thought`, `<end_of_turn>` do not get into the visible text;
  extra closing markers are cut both in the worker and at the balancer boundary.
- The SSE filter on the balancer now really works (before it received raw JSON and was
  a no-op) and does not discard the chunk entirely during cleanup.
- The final `[DONE]`/`done:true` is emitted **always** and exactly once (before —
  only with auto-continuation enabled, otherwise the stream ended silently).
- Live check — `node scripts/verify-stream-r231.js`; the client contract
  (OpenAI + Ollama) — `scripts/clients/contract-suite.js` with a new block 6.

### RPC layout: a measured gain
- On `Qwen3.8-27B-UD-Q4_K_M` (15.33 GiB, `ctx=16384`, KV q8_0) a layout onto the donor
  gives **≈2.9× in generation speed** (136 s → 46 s for 96 tokens), the layout
  changes from 20/66 layers on the GPU to 48/66; loading barely gets more expensive (+2.5 %).
- Methodology and limitations — [rpc-benchmark-qwen38.md](../features/rpc-benchmark-qwen38.md);
  reproduction — `pwsh -File scripts/bench-rpc-qwen38.ps1 -Mode both`.

## 3. Upgrading from rc1

1. **Images:** `balancer:r231-stream`, `cppworker:gpu-r231-stream`,
   `webui:r229m-authproxy`, `imageworker:cuda-75-86-120` (tags — in
   `deployments/.env`).
2. **Mandatory for models ≥ ~15 GB:** `CPPWORKER_LOAD_STALL_SEC=1200` in
   `deployments/.env` (the default 300 s cuts off loading on a slow disk).
3. **Layout:** mode — `PUT /api/v1/backends/{id}/rpc-layout`
   `{"mode":"auto"|"on"|"off"}`; `auto` — the recommendation. Before measuring
   the gain, check the link (`POST .../measure-link`).
4. **AutoTune:** nothing needs to be enabled (the global/per-model flag as before);
   after the upgrade the recommendations are computed from the actual memory.
5. **Clients:** no restart required; for Cline/OpenWebUI the stream has become
   contractual (markers/duplicates/`[DONE]`).

## 4. Known limitations

- The manual smoke on A10 from [v1.0-smoke-checklist.md](v1.0-smoke-checklist.md) —
  is still a manual step before the final tag.
- The RPC gain depends on the link and the VRAM of the donor; on a slow link a
  regression is possible — measure, do not assume.
- Loading a 15 GB model on this stand takes ~5 minutes (disk), this is not a regression
  of the code; it is cured by `CPPWORKER_LOAD_STALL_SEC` and the OS page cache.
- Historical CHANGELOG entries contain internal addresses/names of past stands
  (history, not secrets); the current configs are only in `deployments/.env` (gitignored).
