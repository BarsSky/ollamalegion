## 4. Живые дефекты, найденные при разборе (все — проверено по коду)

### 4.1 Сайдбар теряет «Диагностику» и «Справку и шаблоны»
`app.js:143` → `SettingsUI.setupModeSelector()` → `settings-ui.js:120-125` (radio `standard` уже `checked`) →
`showModeFields('standard')` → `:183` `updateVariantSections('standard')` → `:237-253` прячет **все** `.nav-item`,
которых нет в `navMap`. В списке нет `diagnostics`, `reference`, `health`, `virtual-models`. `applyChrome()`
(`backend-type-filter.js:617-633`) восстанавливает только `gguf`/`image`/бейдж. Комментарий `index.html:144-148`
обещает обратное; тест `backend-type-filter-nav-r94.test.js` мокает 4 пункта и этого не видит.
**Следствие:** страница «Справка и шаблоны» (R493) в сайдбаре не появляется — вход только по `#reference`.

### 4.2 Два пункта меню ведут в пустоту
`index.html:116` (`virtual-models.html`) и `:127` (`health.html`) — `<a>` с `data-page`; `app-listeners.js:85`
делает `preventDefault()` и зовёт `switchPage(...)`; секций `#virtual-models-page`/`#health-page` нет, веток в
`refreshPage` (`app.js:303-461`) нет → снимается `.active` со всех страниц, остаётся пустая область, а заголовок
показывает сырой ключ (`header.virtual-models`/`header.health` в i18n **отсутствуют**, `I18N.t` возвращает ключ).

### 4.3 R118 (спрятать режимы) противоречит R112 (показывать всегда)
`backend-type-filter.js:647-653` присваивает `card.style.display = ''` **всем** `.mode-card[data-mode]`, и
`toggleModeCards` вызывается из `updateUI()` на каждом cluster-update (`app.js:1162-1163`). Первый тик снимает
inline `display:none` из `index.html:1483,1489,1495,1501` → скрытые режимы снова видны, `mode-wizard` достижим.
Тест `unverified-modes-hidden-r118.test.js` проверяет статический файл и этого не ловит.
**Это вопрос решения владельца, а не баг-фикс** (см. §6).

### 4.4 `SettingsUI.updateModeCards` вызывается, но не экспортируется
Определён `settings-ui.js:147`, отсутствует в объекте экспорта `:659-678`, при этом вызывается из `app.js:1565`,
`config-io.js:329`, `mode-wizard.js:397` → `TypeError`; в `applyServerConfig` после этой строки не выполняются
`showModeFields` (1566) и весь блок агента (1571-1583). Внутренние пути (`syncModeFromServer:137`,
`setupModeSelector:123`) используют локальную функцию и работают — поэтому дефект виден только снаружи.

### 4.5 `auth.js` не загружается на трёх служебных страницах
`virtual-models.html:329-330`, `rpc-status.html:201-202`, `tp-pipeline.html:167-168`:
`<script src="…config.js">` + вложенный `<script defer src="…auth.js"></script></script>`. Вложенный тег — текст
внутри элемента с `src`, поэтому игнорируется: `config.js` грузится, `auth.js` — **никогда**. Ровно тот комментарий
рядом (`virtual-models.html:325-327`) объясняет, зачем auth.js нужен (иначе 401 на `GET /api/v1/virtual-models`).
В `health.html:485` подключение корректное — эталон.

### 4.6 Мастер инициализации: пустой экран после импорта — **СДЕЛАНО (R543)**
`setup-wizard.js:571-573` ставил `currentStep = 5` при `totalSteps = 4` → `renderStepContent` не находит `case 5`

**R543 (0.7.346):** шаг зажимается в `[1, totalSteps]` у единственного рендерера (`renderStep`), импорт ведёт на

## 5. Нужна ли первичная инициализация — нет

Что мастер (4 шага) реально делает сегодня: приветствие + импорт → «состав кластера» (`SetupPlan.mount`) → 4 лимита
(gpu/vram/cpu/ram) → сводка → один `PUT` с `{initialized:true, backendEngine, 4 лимита}`.

Уникального — **ничего**:
- `initialized` только скрывает модалку (`isInitialized` → `cfg.initialized === true`);
- «состав кластера» дублируется на странице «Бэкенды» (`backend-merge.js`);
- лимиты дублируются в настройках (`index.html:1725-1739`), причём 3 из 4 не влияют на решения (аудит §S-2: пороги
  90/95/98 зашиты в `slot_manager.go:191,214,227`);
- `backendEngine` отправляется **всегда как `llama_cpp`** (`:671-673`), потому что `wizardState.backendType`
  инициализирован `'llama_cpp'`, а выбрать его нечем (R195) — то есть каждый свежий стенд получает пин, который
  унификация типов как раз отменяла.

Пять причин, почему унификация «убила» мастер: тип не выбирается (R195), движок выводится из состава (R112),
страницы движков появляются сами (R94), режимы из мастера убраны (R107), а сам `#section-mode` уже помечен
«Устарело» и подлежит удалению (§6).

**Рекомендация:** заменить мастер карточкой первого запуска на дашборде («стенд пуст → добавьте бэкенд /
импортируйте конфиг»), которая ставит `initialized:true` при первом действии. Если нужен входной сценарий —
2 шага без полей ввода: «что найдено в кластере» (автодиагностика) + «Готово».
