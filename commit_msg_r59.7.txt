fix(webui): R59.7 — GGUF backends list now renders (4th & 5th IIFE export traps)

User report (this turn): "в webui еще осталась проблема с отображением
существующих бэкендов gguf models - ничего нет хотя в dashboard и монитор
все отображается".

Same root cause as R59.3, R59.5, R59.6: `const X = (function(){...})()`
without a trailing `window.X = X` (or direct `window.X = X` in the
declaration). This is the 4th and 5th occurrence in 7 commits — it's
a systemic refactor smell, not a one-off mistake.

## Bug 1: `window.GgufApi` undefined (gguf-api.js)

`webui/js/modules/gguf-api.js:14` declared `const GgufApi = (function () { ... })();`
without ever assigning to `window.GgufApi`. The IIFE ended at line 1023 with
just `})();` and no `window.GgufApi = GgufApi;`.

`gguf-renderer-refresh.js:34` (M.refreshBackends) tried to call
`window.GgufApi.listBackends()`. Both halves failed:
- `window.GgufApi` was `undefined` → caught by `typeof` check on line 35
- `Api.listBackends` was never defined either — only `Api.fetchGgufBackends()`

Result: `refreshBackends` returned `Promise.resolve()` silently →
`state.registeredBackends` stayed empty → GGUF page rendered
"no registered backends" even though the same backend was visible on
Dashboard and Monitor.

Fix:
1. `webui/js/modules/gguf-renderer-refresh.js:30-50` — call
   `Api.fetchGgufBackends()` directly. The endpoint already returns the
   deduped list of GGUF backends (api.md §GGUF), which is exactly
   what the GGUF page wants to display.
2. `webui/js/modules/gguf-api.js:1024-1033` — add `window.GgufApi = GgufApi;`
   so future modules can find it (GgufApi is the per-cppworker surface
   with setUrl / loadModel / unloadModel / hfSearch / etc.; the export
   is purely additive).

## Bug 2: `window.Utils` undefined (utils.js)

`webui/js/modules/utils.js:5` declared `const Utils = { ... };` (no IIFE,
just a plain object literal) without ever assigning to `window.Utils`.

`webui/js/modules/gguf-renderer-list.js:99` calls
`window.Utils.escapeHtml(b.id)`. After Bug 1 was fixed and backends
arrived in `state.registeredBackends`, the renderer crashed on every
backend with:

  refreshBackends failed: TypeError: Cannot read properties of
  undefined (reading 'escapeHtml')
    at http://localhost:18083/js/modules/gguf-renderer-list.js:99:118

This is the same class of bug as Bug 1: 4 occurrences in this commit
series (R59.3 WebSocketManager, R59.6 showToast, R59.7 GgufApi, R59.7
Utils). The fix is the same single-line pattern.

Fix: `webui/js/modules/utils.js:285-294` — add `window.Utils = Utils;`.

## Why this didn't trigger R59.5 page-coverage test

`scripts/diag_webui_pages.py` iterates over nav items and for each
checks (a) page_errors==0, (b) api_401==0, (c) rendered==True via a CSS
selector match. The GGUF page did render `#ggufDetailPanel` (Bug 1 didn't
crash, it silently returned empty data), and it didn't throw any
pageerror (the `console.warn` from `refreshBackends`'s catch is not a
`pageerror`). So the test went green while the user saw an empty
backends list.

The R59.5 test caught R59.5's R59.5-crash because the crash threw a
uncaught exception. Silent-failure-via-`console.warn` is a different
class of bug; to catch it the test would need to assert non-empty
state on the GGUF page. Tracked as a follow-up to R59.7 (add
`gguf-page-rendered-backends-count > 0` to the smoke test).

Cross-project rule: any JS file that ends with `const X = (function()
{ ... })();` without a trailing `if (typeof window !== 'undefined')
window.X = X;` should be treated as a regression candidate. See
memory entry "App-context IIFE refactor: export App.X AND window.X"
for the grep idiom that catches the entire class.
