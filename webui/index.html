    ▼ Основные настройки
    ? Resource-Aware - выбор по GPU/VRAM/CPU + скоринг (рекомендуется)
    Least Connections - наименьшее число активных запросов
    Round Robin - циклическое переключение с учётом веса
    Weighted - пропорционально весу бэкенда
    Model Affinity - приоритет бэкенда с загруженной моделью
    ? Включает полную формулу скоринга v2: бонус за загруженные модели, штраф за очередь и ошибки, прогноз критического состояния. При выключении - упрощённый скоринг (GPU/VRAM/CPU + weight).
    ? Выберите цветовую схему. Применяется мгновенно (без сохранения), синхронизируется с кнопкой в header и горячей клавишей Ctrl+Shift+T.

    ▼ Настройки llama.cpp / GGUF

    Глобальные параметры загрузки GGUF-моделей. Применяются ко всем llama.cpp бэкендам. Могут быть переопределены на странице GGUF для конкретной модели.

    Пресеты:
    ? Число слоёв модели для выгрузки на GPU. -2 = AUTO (cppworker решает по VRAM/размеру), -1 = все слои, 0 = только CPU.
    ? Размер контекстного окна в токенах. Больше = длиннее диалоги, но больше потребление VRAM/RAM. gemma-4 поддерживает до 256K.
    ? Размер батча для инференса. Больше = быстрее на GPU, но больше потребление памяти.
    ? 0=disabled, 1=enabled, -1=auto. cppworker пишет это как defaultFlashAttnType.
    ? Число CPU-потоков. 0 = авто (использовать все логические ядра).
    ? Включает Flash Attention (память-O(n) вместо O(n²)). Рекомендуется — ускорение на длинных контекстах.
    ? Non-Uniform Memory Access. Включай только на NUMA-системах (многосокетные серверы). На десктопе обычно 0.
    ? Memory-map файл модели вместо загрузки в RAM. Экономит RAM, но замедляет cold-start. Рекомендуется true.
    ? Заблокировать страницы модели в RAM (не выгружать в swap). Требует CAP_IPC_LOCK. Обычно не нужно при mmap=true.
    Multi-GPU и распределение
    ? Как распределять слои модели между GPU. vram-ratio (по памяти) — auto. Manual — задать доли вручную. Auto — пусть llama.cpp решает.
    ? Автоматически считать оптимальный tensor split на основе свободной VRAM. Удобно при mixed-GPU.
    ? Доли тензоров для каждого GPU через запятую (например: 0.5,0.5). Сумма должна быть 1.0. Используется только при стратегии Manual.
    ? -1=default, 0=NONE, 1=LAYER, 2=ROW, 3=TENSOR. Режим разбиения модели между GPU.
    ? Индекс GPU для буферов, которые не помещаются в split (например, scratch). 0 = первая карта.
    ? RPC backend для распределённых вычислений (cuda/vulkan/kompute). Оставь default если модель на одном бэкенде.
    ? Полностью загрузить модель в RAM (без mmap). Используется редко — mmap=true обычно лучше.
    KV-cache
    ? Тип квантизации KV-cache. q8_0 экономит ~50% VRAM, q4_0 — ~75%, с минимальной потерей качества.
    ? Держать KV-cache в RAM (не выгружать на GPU). Полезно при нехватке VRAM, но сильно замедляет.
    RoPE и YaRN (расширение контекста)
    ? Базовая частота RoPE. Стандарт: 10000. Для некоторых моделей (LLaMA-3, gemma) нужно 500000-1000000.
    ? Множитель частоты RoPE. Стандарт: 1.0. Используется при scaling_type=linear.
    ? Метод расширения контекста: none (стандарт), linear (линейная экстраполяция), yarn (умное расширение для длинных контекстов).
    ? Фактор расширения контекста (например, 4.0 = 4x больше контекста через RoPE/YaRN).
    ? Коэффициент экстраполяции YaRN. Больше = агрессивнее расширение, выше риск галлюцинаций. Стандарт: 1.0.
    ? Коэффициент внимания YaRN. Стандарт: 1.0. Уменьшай если модель теряет фокус на длинных контекстах.
    ? Beta-fast параметр YaRN. Стандарт: 32. Низкое = более агрессивное внимание к старым токенам.
    ? Beta-slow параметр YaRN. Стандарт: 1. Низкое = более агрессивное внимание к новым токенам.
    Производительность и метрики
    Reasoning / Thinking
    ? Включает thinking-режим для моделей, которые его поддерживают (gemma-4, deepseek-r1, qwen3-thinking). Парсер автоматически извлечёт think-блоки в отдельное поле reasoning_content.
    ? Максимум токенов, которые модель может потратить на размышления перед ответом. 0 = без лимита. Рекомендуется 1024-8192 для большинства reasoning-моделей.
    ? Эпсилон для RMS-нормализации. Стандарт: 1e-5. Менять обычно не нужно.
    ? Автовыгрузка модели из VRAM после N минут простоя. 0 = выключено (по умолчанию).
    ? Включает Prometheus-style метрики (токены/сек, latency, queue depth). Видны в Monitor page.
    ? Сколько секунд хранить метрики в памяти. 0 = хранить вечно. По умолчанию 3600 (1 час).
    Runtime overrides active sidecar
    /app/data/runtime-overrides/llama-cpp.json

    Текущие значения отличаются от config.json (host = source of truth). Изменения сохранены в sidecar-файле и переживают restart контейнера. "Reset" стирает override и возвращает значения из config.json.

    Per-Model Profiles (n_ctx override)

    Per-model profile переопределяет contextLength для конкретной GGUF-модели. Применяется в 3-tier резолвере между body и per-backend default. Используйте это для моделей с большим окном (gemma-4 - до 256K) или для ускорения малых моделей коротким окном.

    Нет настроенных профилей. Создайте первый, чтобы переопределить n_ctx для конкретной модели.
