# Аутентификация WebUI OllamaLegion (полноценная, вариант 2)

Статус: в работе (цель `goal-cbcd54e4`).
Дата: 2026-10-21.

## Зачем

WebUI открыт в локальной сети, пользовательского входа нет: любой, кто открыл страницу,
получает вшитый API-токен и работает как администратор. При этом оператор/админ один, но
может заходить с разных машин — и должен видеть АКТУАЛЬНОЕ состояние, а не своё локальное
(второй браузер показывал другой набор данных из-за localStorage-фильтра, см. отдельную
задачу «аудит состояния WebUI»).

## Что уже есть (не ломать)

- `X-API-Token` — админский токен, обязателен для `/api/v1/*` (`AuthMiddleware`).
- Токен вшивается в `WEBUI_CONFIG` (это и есть дыра: страница отдаёт его любому).
- Внешние клиенты (Cline, openai-клиенты) ходят с токеном — обратная совместимость
  обязательна.

## Целевая модель

1. **Пользователи** — файл `config/users.json` (права 0600) или переменные окружения для
   первого запуска:

   ```json
   {"users":[{"name":"admin","role":"admin","password_hash":"$argon2id$..."}]}
   ```

   Пароли — только хеши (argon2id, через `golang.org/x/crypto/argon2`). В репозиторий
   ничего с паролями не попадает.
2. **Сессии** — на сервере (in-memory + опционально файл в `data/sessions.json`), cookie
   `ol_session`: `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS, TTL 12 часов,
   скользящее продление при активности, `id` — 32 случайных байта.
3. **Роли**:
   - `admin` — полный доступ (изменение профилей, загрузка/выгрузка, настройки, роли).
   - `viewer` — только чтение (`GET`), мутирующие запросы → `403` с причиной.
4. **CSRF**: для мутирующих запросов (POST/PUT/DELETE) требуется заголовок
   `X-CSRF-Token`, значение — токен сессии, отданный в `GET /api/v1/auth/me`;
   `SameSite=Lax` — вторая линия обороны.
5. **Break-glass**: `X-API-Token` остаётся валидным (для Cline/скриптов и на случай потери
   пароля), но **не** отдаётся больше в `WEBUI_CONFIG`; браузер работает только через сессию.
6. **Эндпоинты**:
   - `POST /api/v1/auth/login` `{name,password}` → `Set-Cookie` + `{user:{name,role},csrf}`;
   - `POST /api/v1/auth/logout` → гасит сессию;
   - `GET  /api/v1/auth/me` → `{authenticated, user, csrf}`;
   - `GET  /api/v1/auth/users` (admin) — список пользователей без хешей;
   - `PUT  /api/v1/auth/users` (admin) — создание/смена пароля (запись в `users.json`).
7. **Безопасность по умолчанию**: если `users.json` отсутствует — WebUI показывает экран
   первого запуска «создайте администратора» (запись возможна только локально или с
   `X-API-Token`), чтобы не остаться с открытой панелью и не заблокировать оператора.

## UI

- Оверлей входа (имя/пароль), кнопка выхода в шапке, индикатор роли;
- при `viewer` мутирующие кнопки отключены с подсказкой «нужны права администратора»;
- токен из страницы убирается: `WEBUI_CONFIG` больше не содержит `API_TOKEN`;
- состояние (роли, списки) не хранится в localStorage — источник истины сервер.

## Тесты

- Go: логин (верный/неверный пароль), TTL и продление, logout, роль viewer → 403 на
  мутирующих, CSRF без заголовка → 403, break-glass токен продолжает работать,
  отсутствие `users.json` → экран первого запуска без открытого доступа.
- JS: экран входа/выхода, скрытие админских действий для viewer.
- Живьём: curl (логин, me, мутирующий запрос с/без CSRF, viewer → 403, logout) и
  Playwright два контекста — admin видит и меняет, viewer читает; второй браузер видит
  применённые параметры (это же проверяет кросс-браузерное состояние).

## Порядок работ

1. План + модель угроз (этот файл).
2. Сервер: пользователи, argon2, сессии, login/logout/me, CSRF, роли в middleware.
3. Тесты сервера.
4. UI: вход/выход, роль, снятие токена из страницы.
5. Тесты UI + живые проверки (curl + Playwright).
6. CHANGELOG, документация, инструкция оператору (как задать пароль, что делать при потере).

## Открытые вопросы к оператору (можно ответить по ходу)

- сколько пользователей нужно и какие имена (пока: один `admin`, второй `viewer`);
- включать ли HTTPS (иначе cookie `Secure` не ставится, пароль идёт по сети в открытом
  виде — для локальной сети допустимо, но лучше reverse-proxy с TLS);
- TTL сессии (по умолчанию 12 часов) и нужно ли «запомнить меня».
