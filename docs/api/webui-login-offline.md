# Вход в WebUI на изолированном (оффлайн) стенде — R270

Короткая инструкция: почему «параметры из env не пускают» и как это проверить.

## Как устроен вход

| Что | Где | Примечание |
|---|---|---|
| Логин/пароль администратора | `LB_ADMIN_USER`, `LB_ADMIN_PASSWORD` (env контейнера **балансера**) | окно панели/WebUI этих переменных не читает |
| Файл пользователей | `LB_USERS_FILE` (по умолчанию `/app/data/users.json` — том `balancer_data`) | должен быть **на запись**, иначе админ живёт только в памяти |
| Файл сессий входа | `LB_SESSIONS_FILE` (по умолчанию рядом с users.json) | переживает рестарт контейнера |

Порядок применения при старте:

1. читается файл пользователей;
2. если заданы `LB_ADMIN_USER` + `LB_ADMIN_PASSWORD` и такой пользователь есть —
   пароль сверяется и, при отличии, **обновляется** (source `env+file`);
3. если такого пользователя нет — он добавляется как администратор;
4. если файла нет и список пуст — создаётся один администратор из env (source `env`);
5. если записать файл не удалось — учётка работает, но **только до рестарта**
   (в `/auth/me` будет `bootstrap.persisted = false` с причиной).

Пароль из env **не обрезается**: пробелы и спецсимволы значимы.

## Почему «задал в env, а не пускает» — типовые причины

Проверять в этом порядке (каждая проверка — одна команда):

1. **Переменные не дошли до контейнера балансера** (самая частая причина).
   ```
   docker exec ol-stack-balancer env | grep LB_ADMIN
   ```
   Пусто → в `docker-compose.stack.yml` нет проброса. Нужно:
   ```
   - LB_ADMIN_USER=${LB_ADMIN_USER:-}
   - LB_ADMIN_PASSWORD=${LB_ADMIN_PASSWORD:-}
   - LB_USERS_FILE=${LB_USERS_FILE:-/app/data/users.json}
   - LB_SESSIONS_FILE=${LB_SESSIONS_FILE:-/app/data/sessions.json}
   ```
2. **Спецсимволы в пароле и `.env`.** В `.env` знак `$` интерполируется, `#` после
   значения начинает комментарий. Пароль с ними нужно писать в кавычках
   (`LB_ADMIN_PASSWORD="a$b#c"`) либо без этих символов. Проверка — сравнить то,
   что реально в контейнере (п.1), с тем, что вы вводите в форме.
3. **Файл пользователей только для чтения** (`/app/config` смонтирован `:ro`).
   ```
   docker exec ol-stack-balancer ls -l /app/data/users.json   # путь из LB_USERS_FILE
   ```
   Смотреть `bootstrap.persisted` в ответе `GET /api/v1/auth/me` — `false` значит
   «применилось в памяти, после рестарта пропадёт».
4. **Старый `users.json` с другого стенда.** При заданных `LB_ADMIN_*` пароль
   обновится автоматически (R203/R270), но если env пуст — вход будет только
   старыми учётками.
5. **Половина пары в env** (задали имя, забыли пароль или наоборот) — в логе при
   старте будет `auth bootstrap … reason="LB_ADMIN_USER/LB_ADMIN_PASSWORD заданы
   не полностью"`.

## Диагностика одной строкой

```
docker logs ol-stack-balancer 2>&1 | grep "auth bootstrap"
```

Строка содержит: `source` (`env` | `env+file` | `file` | `none`), `env_applied`,
`users`, `path`, `writable`, `persisted`, `reason`. Пароль не печатается никогда.

API (без секретов):

```
curl -s http://127.0.0.1:18081/api/v1/auth/me | jq .bootstrap
```

`usersConfigured:false` означает «файла нет и env не задан» — тогда панель честно
отвечает 503 с подсказкой, что именно нужно выставить.

## Сброс пароля офлайн

```
# 1) задать новый пароль в deployments/.env
LB_ADMIN_USER=skyadmin
LB_ADMIN_PASSWORD="новый-пароль"
# 2) перезапустить только балансер
cd deployments && docker compose up -d loadbalancer
# 3) убедиться, что применилось
docker logs ol-stack-balancer 2>&1 | grep "auth bootstrap"
```

Если `persisted:false` — сначала починить путь/права (`LB_USERS_FILE` в
записываемый том), иначе следующий рестарт снова не пустит.
