# Недостающие компоненты image-набора (VAE / text encoder)

R710 (2026-11-24). Документ отвечает на один вопрос оператора: **вердикт говорит
«не хватает VAE, text encoder (LLM)», а в репозитории этих файлов нет — что
делать?** Ответ: добавить их из другого репозитория прямо со страницы, кнопками
«Добавить VAE (по умолчанию)» / «Добавить text encoder (по умолчанию)» /
«Выбрать из другого репозитория…».

## 1. Почему компонентов нет в самом репозитории модели

DiT-семейства (Qwen-Image, FLUX, SD3, Z-Image, Chroma) в stable-diffusion.cpp
грузятся не одним файлом, а набором:

```
sd-server --diffusion-model qwen-image-Q4_K_M.gguf --vae ae.safetensors --llm qwen3vl_8b_int8.safetensors
```

Авторы моделей публикуют **только diffusion-веса** (это то, что они тренировали),
а VAE и текстовый энкодер — общие для всего семейства и лежат отдельными
репозиториями (экспорты ComfyUI, официальные репозитории Stability/BFL,
квантованные GGUF-энкодеры). Типичный пример:

| репозиторий | что внутри |
| --- | --- |
| `Comfy-Org/Qwen-Image-Edit_ComfyUI` | только diffusion-файлы (+ LoRA) — ни VAE, ни энкодера |
| `Comfy-Org/Qwen-Image_ComfyUI` | `split_files/vae/qwen_image_vae.safetensors`, `split_files/text_encoders/…` |
| `abenzerps/Qwen-Image-2.1-Uncensored-GGUF` | `vae/qwen_image_2.1_vae_bf16.safetensors`, `text_encoders/qwen3vl_8b_int8_convrot.safetensors` |

Поэтому «скачать модель» и «скачать набор» — разные действия, и вердикт
совместимости (R696) честно говорит, чего в наборе не хватает.

## 2. Что нужно семейству

Каталог (`GET /api/v1/image/components/catalog?family=<f>`) отдаёт то же, что и
таблица ниже; значения проверены запросом к HF tree API (размер — фактический).

| семейство | обязательные роли | стандартный компонент (`default`) |
| --- | --- | --- |
| `qwen_image` | `vae` + `llm` | VAE 242 МиБ — `Comfy-Org/Qwen-Image_ComfyUI`; энкодер 8.7 ГиБ — `abenzerps/Qwen-Image-2.1-Uncensored-GGUF` (Qwen3-VL 8B int8) |
| `flux` | `vae` + `clip_l` + `t5xxl` | VAE (ae) 320 МиБ — `lodestones/Chroma`; CLIP-L 235 МиБ — `comfyanonymous/flux_text_encoders`; T5-XXL Q4_K_M 2.7 ГиБ — `city96/t5-v1_1-xxl-encoder-gguf` |
| `flux2` | `vae` + `llm` | VAE FLUX.2 321 МиБ и Mistral Small 3 fp8 16.8 ГиБ — `Comfy-Org/flux2-dev` |
| `sd3` | `vae` + `clip_l` + `clip_g` + `t5xxl` | `stabilityai/stable-diffusion-3.5-large` (репозиторий **gated**: нужен HF-токен с принятой лицензией) |
| `z_image` | `vae` + `llm` | VAE 320 МиБ и Qwen3-4B 7.7 ГиБ — `Comfy-Org/z_image_turbo` (есть fp8_mixed на 5.4 ГиБ) |
| `chroma` | `vae` + `t5xxl` | VAE 320 МиБ — `lodestones/Chroma`; T5-XXL Q4_K_M — `city96/t5-v1_1-xxl-encoder-gguf` |
| `sdxl` | — (all-in-one) | VAE 320 МиБ — `stabilityai/sdxl-vae` (полезно, когда декодер чекпойнта даёт артефакты) |
| `sd15` | — (all-in-one) | VAE 320 МиБ — `stabilityai/sd-vae-ft-mse` |
| любое другое | — | каталога нет: только ручной путь (см. §4) |

Колонка «default» — это ровно те компоненты, для которых в интерфейсе появляется
кнопка «Добавить … (по умолчанию)». У роли может быть несколько вариантов
(например, VAE и энкодер у Qwen-Image) — тогда кнопка «по умолчанию» ведёт к
стандартному, а остальные доступны ручным выбором.

## 3. Как это сделать в интерфейсе

**Вкладка HF → карточка репозитория → вердикт.** Под строкой
«не хватает: VAE, text encoder (LLM)» появляются кнопки:

- «Добавить VAE (по умолчанию)» и «Добавить text encoder (LLM) (по умолчанию)» —
  только если в каталоге есть стандартный компонент этой роли;
- «Скачать недостающее (N)» — когда стандартных компонентов два и больше
  (добавляет все сразу одним подтверждением);
- «Выбрать из другого репозитория…» — ручной путь: поле «Репозиторий HF»,
  кнопка «Показать файлы», список файлов с ролями (их предлагает сервер — та же
  эвристика, что в списке файлов модели), галочки и «Добавить к набору».

Перед запуском показывается подтверждение с числами:

```
Будет добавлено: VAE split_files/vae/qwen_image_vae.safetensors (242 МБ) из Comfy-Org/Qwen-Image_ComfyUI
Это стандартный для семейства qwen_image компонент.
Лицензия: apache-2.0
Файл добавится к набору и скачается вместе с остальными файлами.
```

После добавления компонент виден отдельной строкой в блоке вердикта (роль, файл,
репозиторий, размер, кнопка «убрать») и уходит в общий POST `/api/hf/bundle` со
своим репозиторием. Проверка набора пересчитывается сразу: добавленная роль
исчезает из «не хватает», и остаётся следующий шаг.

**Страница «Модели на диске».** У модели с неполным набором в колонке вердикта —
те же кнопки. Здесь компонент добавляется в **уже скачанный** каталог:
POST `/api/v1/image/models/{name}/components` → файл скачивается в каталог модели,
роль прописывается в `profile.json`, воркер пересканирует реестр, и вердикт
пересчитывается. Существующие файлы не перезаписываются: роль `diffusion` через
эту ручку добавить нельзя, а файл, чьё имя уже занято другой ролью, отвергается
конфликтом `409`. Прогресс — обычный, на вкладке «Загрузки» (`trackingId` вида
`<модель>~components~<роль>`), отмена — кнопкой «Отменить».

Предупреждение после добавления остаётся в карточке модели: «Добавлено по
умолчанию: VAE из … (лицензия: apache-2.0). Проверьте лицензию перед публикацией
результатов».

## 4. Если каталог не знает семейство

Для семейств вне таблицы (`other`, Wan, Pixar и т.п.) в интерфейсе **нет** кнопок
«по умолчанию» — зато остаётся «Выбрать из другого репозитория…», и там честно
сказано: «Каталога стандартных компонентов для семейства «wan» нет: укажите
репозиторий и файл вручную». Порядок действий:

1. найдите репозиторий, где лежит нужный компонент (VAE/энкодер) для вашей модели;
2. «Выбрать из другого репозитория…» → вставьте `owner/repo` → «Показать файлы»;
3. отметьте файл и проверьте роль в селекте (сервер предлагает её по имени);
4. «Добавить к набору» → подтверждение → скачивание вместе с набором.

Для уже скачанной модели на странице «Модели на диске» ручной путь спрашивает
репозиторий и номер файла из списка.

## 5. Лицензии

Компоненты — **чужие файлы из чужих репозиториев**. Каталог показывает лицензию
из карточки HF (`apache-2.0`, `mit`, `openrail++`, `other`), но:

- `other` не означает «можно всё»: у Stability/BFL и у неофициальных переупаковок
  свои условия (часто — некоммерческая лицензия или ограничения на использование
  результатов);
- часть репозиториев **gated**: скачивание требует HF-токена с принятой лицензией
  (в каталоге это отмечено в примечании к компоненту);
- добавляя компонент «по умолчанию», вы принимаете решение за себя: интерфейс
  предупреждает об этом и в подтверждении, и в карточке модели после установки.

## 6. Технические детали (для отладки)

- каталог: `GET /api/v1/image/components/catalog?family=qwen_image&roles=vae,llm`
  (данные — `internal/sdbackend/components.go`, отдаются локально, бэкенды не
  нужны);
- установка: `POST /api/v1/image/models/{name}/components` с телом
  `{role, repo, files[], revision?, default?, modelDir?}` → `202` +
  `trackingId`; ошибки — кодами: `409 role_already_present` (в ответе
  `currentFile`), `400 invalid_path` (путь вне каталога моделей), `404
  bundle_not_found` / `component_file_not_found` (с `available` — что есть в
  репозитории), `413 component_too_large` (лимит 20 ГиБ на запрос), `502
  component_repo_unavailable`;
- прогресс/отмена — существующие ручки: `GET /api/hf/progress?bundleId=<trackingId>`,
  `POST /api/hf/cancel {"bundleId": "<trackingId>"}`;
- идемпотентность: повторный вызов при занятой роли — `409` без обращения к сети;
  файл, уже лежащий в каталоге, не скачивается заново (в ответе `reused`).
