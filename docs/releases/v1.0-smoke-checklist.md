# v1.0 — manual smoke checklist on A10 24 GB

**Why:** the only step before the final `v1.0` tag that cannot be done
in CI — check the behavior on real hardware with a real model (A10 24 GB +
Qwen3-A3B / Qwen3.8-27B). Below are 12 scenarios; each has an **expected
result** and **how to check**, without reading code.

**Preparation (once):**

```powershell
# stack is up
cd deployments
docker compose -f docker-compose.cppworker-bundled-with-agent.yml up -d
docker ps --format '{{.Names}}\t{{.Status}}' | Select-String ol-bundled

# addresses
$B = 'http://127.0.0.1:18080'          # balancer (client API)
$A = 'http://127.0.0.1:18081'          # admin API
$T = 'changeme-bundled-with-agent-token'
```

Mark `PASS`/`FAIL` in the table at the end; for each FAIL it is useful to attach
the command output — that way the analysis will not require a repeat run.

---

## 1. Model loading and layout mode

```powershell
curl.exe -s -H "X-API-Token: $T" -H 'Content-Type: application/json' `
  -d '{"name":"qwen3.8:latest","contextSize":32768}' "$B/api/v1/gguf/backends/cppworker-gpu-bundled-agent/proxy/api/models/load"
# wait for state=loaded
curl.exe -s "$B/api/v1/cppworker/models" | Select-String 'n_ctx_degraded|max_exact_fit_n_ctx|gpu_layers'
```

**Expected:** the model is `state=loaded`; `gpu_layers > 0` (not CPU-only);
`n_ctx_degraded` reflects reality (at 32768 and a ceiling in the tens of thousands — `false`);
`max_exact_fit_n_ctx` is present. **Regression:** `gpu_layers=0` or
`n_ctx_degraded=true` with a small context.

## 2. Response streaming (Ollama API)

```powershell
curl.exe -s -N -H "X-API-Token: $T" -H 'Content-Type: application/json' `
  -d '{"model":"qwen3.8:latest","messages":[{"role":"user","content":"Reply with exactly: OK"}],"stream":true}' `
  "$B/api/chat" | Out-File .\chat.txt
```

**Expected:** exactly **one** `"done":true` frame; in it `message.content` is empty;
the text arrives only in deltas; `eval_count` and `prompt_eval_count` are present.
**Regression:** two `done:true`; the full text in `done` (clients that concatenate
chunks will show the answer twice).

## 3. OpenAI-compatible path

```powershell
curl.exe -s -N -H "X-API-Token: $T" -H 'Content-Type: application/json' `
  -d '{"model":"qwen3.8:latest","messages":[{"role":"user","content":"hi"}],"stream":true}' `
  "$B/v1/chat/completions" | Select-String 'delta|finish_reason|\[DONE\]'
```

**Expected:** in the final frame (`finish_reason` is not empty) `delta.content` is empty;
then a usage frame and `[DONE]`.

## 4. Tool calling (a Cline-like request)

```powershell
# a request with tools; check that tool_call arrives as an object, not as a string
curl.exe -s -H "X-API-Token: $T" -H 'Content-Type: application/json' --data-binary "@tools.json" `
  "$B/api/chat" | Select-String 'tool_calls|done_reason'
```

**Expected:** `done_reason: "tool_calls"`, `message.tool_calls[].function.arguments`
— an **object** (not a JSON string), `content` is empty.

## 5. Context: a request above the ceiling

```powershell
curl.exe -s -o out.json -w "%{http_code}`n" -H "X-API-Token: $T" -H 'Content-Type: application/json' `
  -d '{"name":"qwen3.8:latest","contextSize":999999}' `
  "$B/api/v1/gguf/backends/cppworker-gpu-bundled-agent/proxy/api/models/load"
```

**Expected:** `422`, `code=n_ctx_infeasible`, the body contains `max_viable_n_ctx` /
`hard_max_n_ctx` and a clear hint. **Regression:** `202` and a subsequent attempt
to load something obviously impossible.

## 6. Context: a request between the report and the ceiling

Repeat p.1 with `"contextSize":60000` (if the hardware ceiling is higher).

**Expected:** either `202` and a **successful** load (`state=loaded`, the actual
`context_size` = the requested one), or an honest refusal with numbers. Not expected:
"accepted → hung forever".
**Measurement:** the time until `state=loaded` (for 27B at 60000 — about 7–8 minutes versus
~2.5 at 32768; this is the normal price of a large context).

## 7. Queue and fairness

```powershell
# 4 concurrent requests with a capacity of 1
1..4 | ForEach-Object -Parallel {
  curl.exe -s -o "r$_.json" -w "%{http_code}`n" -H "X-API-Token: $T" -H 'Content-Type: application/json' `
    -d '{"model":"qwen3.8:latest","messages":[{"role":"user","content":"count to 20"}],"stream":false}' `
    "$using:B/api/chat"
}
curl.exe -s -H "X-API-Token: $T" "$A/api/v1/queue/stats" | Select-String 'admission|current_size'
```

**Expected:** all 4 — `200`; three of the four have `X-Queue-Position` in the headers;
`admission.served > 0`. **Regression:** `503` on occupied slots.

## 8. Notification about a loading failure

```powershell
curl.exe -s -o e.json -w "%{http_code}`n" -H "X-API-Token: $T" -H 'Content-Type: application/json' `
  -d '{"model":"v1-nonexistent:latest","messages":[{"role":"user","content":"hi"}],"stream":false}' "$B/api/chat"
Start-Sleep 15
curl.exe -s -H "X-API-Token: $T" "$A/api/v1/health/detailed" | Select-String 'recentErrors|v1-nonexistent'
```

**Expected:** non-2xx with a reason; the event in `recentErrors` **without an open
SSE client** (this checks the filling of the ring buffer).

## 9. Replication and failover (2 cppworkers required)

See `docs/plans/2026-09-25-placement-p4-load-kpi.md` (2×cppworker stand).

**Expected:** `replication total=2 loaded=2`; when one copy is `docker stop`ped
the live one serves the requests (no 503); a request that picked the failed replica
moves over within seconds; recovery 20–35 s.

## 10. Placement policy: non-executable strategies

```powershell
curl.exe -s -H "X-API-Token: $T" "$A/api/v1/placement" | Select-String 'executable|sharded|rpc'
```

**Expected:** only `single/pool/replicated/auto` in `executable`; with
`fallback=error` a request with `sharded`/`rpc` gets a `503` with the reason **before**
routing; with `fallback=single` — `200` + `X-LB-Placement-Fallback`.

## 11. Operator dashboard

Open `http://127.0.0.1:8080/` and `/monitor`.

**Expected:** the pages render, there is no `ReferenceError`/`fetchAll failed`
in the browser console; on `/monitor` the backends, resources, the
placement card and the admission queues are visible; notifications (bell) show
failures and degradation.

## 12. Absence of regressions in the logs

```powershell
docker logs --since 2h ol-bundled-cppworker-gpu 2>&1 | Select-String 'SIGABRT|unaligned tcache|panic|VRAM insufficient'
docker logs --since 2h ol-bundled-balancer     2>&1 | Select-String 'panic|fatal'
```

**Expected:** empty.
