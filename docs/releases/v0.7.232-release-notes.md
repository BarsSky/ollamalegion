# v0.7.232 — vision enabled by default (R248)

What works now (release 0.7.232):
- `capabilities.vision: true` is published when the model was loaded with mmproj and
  mtmd confirmed vision support; operator kill switch custom `CPPWORKER_VISION_MMPROJ=0`.
- Images are accepted on both surfaces: OpenAI `content[]` with `image_url`
  (base64 data URL) and Ollama `images[]`; the Anthropic shape
  (`image`/`source.data`) is lifted into `images` by the balancer.
- Streaming image requests: the answer is computed in full (libmtmd prefill is
  synchronous) and emitted as a valid stream — OpenAI SSE
  (delta + finish_reason=stop + [DONE]) and Ollama NDJSON (content + done).
- A model without a projector still rejects images honestly: 415 plus
  `X-Vision-Supported: false`.

Explicit limits (not silent):
- http(s) image links are not downloaded — inline base64 only;
- images are served synchronously, so a streaming answer arrives as one chunk;
- up to 8 images per request, 8 MiB per image; errors are distinguishable
  (`too_many_images`, `image_too_large`, `image_decode_failed`, `image_unsupported_type`).

Live verification (SmolVLM-256M-Instruct-Q8_0 with its mmproj on the stand):
- "Transcribe the exact text in the image" plus a PNG with the word OK returns
  content `OK`; the bridge log shows `[bridge] image prefill: n_past=161 images=1`;
- `stream=true` returns SSE delta ` OK`, `finish_reason=stop`, `[DONE]`;
- gemma-4-E4B (text model, no mmproj) with an image returns 415;
- clients-compat: 8 of 8 checks pass.
