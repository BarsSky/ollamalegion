# v0.7.232 — vision включён по умолчанию (R248)

Что теперь работает:
- `capabilities.vision: true` публикуется, когда модель загружена с mmproj и
  mtmd подтвердил vision; операторский «стоп» — `CPPWORKER_VISION_MMPROJ=0`.
- Картинки принимаются на обеих поверхностях: OpenAI `content[]` с
  `image_url` (data-URL base64) и Ollama `images[]`; Anthropic-форма
  (`image`/`source.data`) поднимается в `images` балансером.
- Стриминговый ответ для image-запросов: ответ считается целиком (префилл
  libmtmd синхронный) и отдаётся валидным потоком — OpenAI SSE
  (delta + finish_reason=stop + [DONE]) и Ollama NDJSON (content + done).
- Модель без проектора честно отбивает картинки: 415 + `X-Vision-Supported: false`.

Ограничения (явные, а не тихие):
- http(s)-ссылки на картинки не скачиваются — только inline base64;
- картинки обслуживаются синхронно, поэтому стриминговый ответ приходит одним чанком;
- лимиты: 8 картинок на запрос, 8 МиБ на картинку; ошибки различимы
  (`too_many_images`, `image_too_large`, `image_decode_failed`, `image_unsupported_type`).

Живая проверка (SmolVLM-256M-Instruct-Q8_0 + его mmproj на стенде):
- «Transcribe the exact text in the image» + PNG со словом OK → content `OK`;
  в логе моста `[bridge] image prefill: n_past=161 images=1`;
- `stream=true` → SSE delta ` OK` + `finish_reason=stop` + `[DONE]`;
- gemma-4-E4B (текстовая, без mmproj) + картинка → 415;
- clients-compat: 8/8 PASS.
