# Решения по полям метрик: «пишется, но не показывается»

Дата: 2026-10-30. Основание: `docs/plans/2026-10-30-abort-and-metrics-audit.md`
(часть 2, находки M1–M6). Правило: по каждому полю — решение с причиной, а не
молчаливое «висит в JSON».

## Решения по остальным полям

| поле | где пишется | читается в WebUI | решение | причина |
| --- | --- | --- | --- | --- |
| `availableVramMb`, `totalVramMb` | поллер `/api/models` | нет | **показывать** (следующий шаг UI): это ответ на «почему не влезает вторая копия» | числа уже есть, дублировать запросы не нужно |
| `vramLocalFreeMb`, `vramRemoteFreeMb`, `vramRemoteNodes` | поллер | нет | **оставить как диагностику** + вывести в tooltip вкладки бэкендов | ценность только при RPC-раскладке; в основном UI это шум |
| `maxVramNCtx`, `modelMaxContext`, `maxFeasibleContext` | поллер | частично (карточка модели показывает `feasibleMaxContext`/`ggufMaxContext`) | **оставить в JSON**, UI не трогать | карточка модели уже отвечает на вопрос «почему окно меньше»; дубль в мониторе не нужен |
| `rpcServersActive` | поллер | нет | **оставить** | используется в отчётах раскладки и в логах R297 |
| `loadedAt` | поллер | нет | **показывать** (следующий шаг UI): «когда модель поднялась» — первое, что спрашивает оператор при «модель вдруг медленная» | |
| `loadingSizeBytes` | воркер → поллер | нет | **показывать вместе с `loadedAt`** в строке загрузки | есть прогресс-блок загрузки, размер в нём уместен |
| `n_heads`, `n_vocab`, `active_queries`, `total_queries` | воркер `/api/models` | нет | **удалить из DTO балансера** (оставить в ответе воркера) | декодируются и выбрасываются: мёртвый вес в JSON балансера |
| `gpuInfo` (в `llamaCpp`) | **никем не пишется** | читается | **удалить чтение** из WebUI | обещание мёртвое: поле не заполняет ни один путь балансера; GPU-данные берутся из `workerInfo`/`gguf-api` |
| `maxRamNCtx` | **никем не пишется** | нет | **удалить из DTO** | мёртвое поле |
| `b.llamaCppMetrics` (путь в WebUI) | ключа не отдаёт никто | читается | **удалить чтение** | мёртвый путь, из-за него фолбэки выглядят «работающими» при пустых данных |
| `device_layers` / `deviceLayers` | поллер (две формы) | читается `deviceLayers` | **оставить обе** | одна — факт из воркера (snake_case), вторая — производная для UI; сверить при следующем касании карточки |

## Почему часть решений — «показывать», а не «удалить»

Правило аудита: поле, которое объясняет отказ или число в интерфейсе, ценнее
удаления. `availableVramMb`/`totalVramMb` и `loadedAt` отвечают на вопросы, с
которыми оператор приходит чаще всего («почему не поднялась вторая копия», «когда
это загрузилось»), и уже есть в JSON — их показ не требует новых запросов.

## Что осталось сделать (UI, отдельным шагом)

1. Показать `availableVramMb`/`totalVramMb` и `loadedAt`/`loadingSizeBytes`
   (вкладка бэкендов и строка загрузки).
2. Удалить мёртвые чтения `gpuInfo` и `llamaCppMetrics` в WebUI и мёртвые поля
   `n_heads`/`n_vocab`/`active_queries`/`total_queries`/`maxRamNCtx` в DTO балансера.
3. После этого прогнать обход WebUI-тестов и живой UI-прогон.

## Не проверено

- Реальные браузерные снимки (в этой среде Chromium не стартует — R319).
- Какие из полей нужны внешним потребителям (Grafana/скрипты оператора): в
  репозитории обращений нет, поэтому решение по ним — «оставить в JSON».
