# v0.7.236 — R476: stand diagnostics in one bundle

**Date:** 2026-11-09 · **Type:** sources + stand images
**Images:** balancer `r261109-1410` (`4c7578a9`), cppworker `gpu-261109-1404`
(`b176967d`), webui `r261109-1410` (`4c7578a9`). Manifest:
`deployments/release-manifest.json`.

---

## 1. Why

Diagnosing a live defect was blocked by access to data, not by code. Versions lived
on one page, window and profiles in the admin UI, flags in `.env` on another host,
backend logs only through `docker logs` on the stand, and the turn summary in the
worker's stdout. Every investigation became a "please also send this" exchange, and
conclusions were drawn from guesses — hence the series of fixes tailored to one
model.

## 2. What is new

| Item | Where | Why |
|---|---|---|
| `request trace` line per request: `request_id`, method, path, status, `duration_ms`, bytes, `backend` | balancer log, `LB_REQUEST_TRACE=off\|summary\|full` | the same `request_id` appears in the worker summary — before, the two logs were unrelated |
| `request_id` in `/api/chat stream response summary` | worker log | one line per turn: `streamed_content_bytes`, `final_content_len`, `tool_calls`, `done_reason`, `dumped_args_instead_of_call` |
| `GET /api/v1/diag/summary` | balancer admin API | versions, flags `set`/`unset`, `nctx_reload`, `nctx_ceiling` with the limiting reason, model profiles with the effective window, cluster, queue |
| `GET /api/v1/diag/bundle` | balancer admin API | zip: summary + balancer logs + worker bundles + `/api/info` per backend + README |
| `GET /api/v1/cppworker/debug/bundle` | worker | zip: `info.json`, `logs.txt` (ring buffer), `last-prompt.json`, `last-stream.json`, `prompt-last.txt`, `request-last.json`, `unparsed-tool-calls.jsonl`, `unparsed-ring.json`, `env.json` (whitelist), README |
| **Diagnostics** page | WebUI (`#diagnostics`) | versions / window+profiles / flags / backends blocks; copy a block with a button, copy a value with a click; "Download diagnostics bundle" |
| `CPPWORKER_LOG_LEVEL` | worker | log level without editing `command` (previously only the `-verbose` flag) |
| `CPPWORKER_LOG_BUFFER_ENTRIES` | worker | log ring buffer; before R476 the worker had none |
| `LB_DIAG_RING` / `CPPWORKER_DIAG_RING` | both | aliases for buffer sizes (primary names win) |
| `CPPWORKER_STREAM_TRACE=1` | worker | `stream_chunks`, `stream_bytes`, `stream_sha256` in the turn summary - byte-level proof that everything was delivered |
| `CPPWORKER_DIAG_KEEP_FILES=N` | worker | previous versions of `prompt-last.txt`/`request-last.json` (`path.1` ... `path.N`) |
| `?since=30m` on `/api/v1/diag/bundle` | balancer | bundle for a time window only (own buffer filtered locally, parameter forwarded to workers) |

`request_id` is now present in DECISION logs too: preflight inputs, the R466 cap,
the R301 growth decision and the exact-token count. Previously a reload could only
be matched to a turn by timestamp.

No secrets in the export: flags go through a whitelist, covered by tests.

## 3. Live verification (numbers, not a retelling)

- `GET :18081/api/v1/diag/summary` → keys `cluster, flags, generated_at,
  model_profiles, nctx_ceiling, nctx_reload, operating_mode, queue_stats,
  version, version_text`; 24 set flags and 9 unset; `nctx_ceiling =
  {envCeiling: 65536, limitedBy: "env"}`; 21 profiles.
- `GET :18081/api/v1/diag/bundle` → 22 KB zip: `summary.json` 22050 B,
  `flags.txt` 1098 B, `balancer-logs.txt`,
  `backends/cppworker-gpu-bundled-agent.info.json` 1155 B,
  `backends/cppworker-gpu-bundled-agent.bundle.zip` 6961 B, `README.txt`.
- Inside the worker bundle: `logs.txt` 17168 B of real ring-buffer records,
  `env.json` 319 B, and missing dumps are marked `*.missing.txt` with a hint about
  `CPPWORKER_DEBUG_*`.
- Balancer log: `{"msg":"request trace","request_id":"req55e2ed4a", ..., "status":200}`.
- WebUI `:18083` serves the page, the module (`window.Diagnostics`, 18965 B) and
  `.diag-table` styles.

**Found and fixed by the live run:** the first bundle contained no worker part —
the balancer used `OllamaPort` (11434) instead of `CppWorkerPort` (18092) and got
`connection refused`. The address now comes from the same helper as inference, and
the failure reason is written into the archive. A unit test could not catch it: it
used an `httptest` server where the port was correct by construction.

## 4. Upgrading the stand

```bash
cd deployments
# .env: BALANCER_TAG=r261109-1410, CPPWORKER_GPU_TAG=261109-1404, WEBUI_TAG=r261109-1410
docker compose -f docker-compose.stack.yml up -d --no-deps loadbalancer cppworker-gpu webui
curl -s http://127.0.0.1:18080/api/version            # build_commit=4c7578a9
curl -s -H "X-API-Token: $CPPWORKER_API_TOKEN" \
     http://127.0.0.1:18081/api/v1/diag/summary | head -c 400
```

Then WebUI → "Diagnostics" → "Download diagnostics bundle".
