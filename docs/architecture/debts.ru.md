     реальный, но НЕ там, где его искал долг.** Проверено на стенде (один мастер

     реальный кандидат).
     - **Что в описании долга оказалось неверным.** Источник каталога —
       `/api/models/files`, а не `/api/tags`; снятые листинги: мастер 3 файла,

       `known=true`, `ageSec=0`. Расхождения «файл есть, каталог не видит» нет.
       И `expandCandidates` каталог НЕ читает вообще: P3 — «healthy, слоты
       свободны, модель не загружена» (`candidate.go:113-136`), узел с файлом на
       диске из P3 выпасть не может.
     - **Что оказалось верным — механизм, на который долг указывал классом
       «каталог не учтён там, где решает».** Этап 3b R493
       (`pickLoadableFreeBackendR493`, `backend_selector.go:347-372`) выбирает
       СВОБОДНЫЙ узел под ЗАГРУЗКУ вместо очереди к занятому — и проверял только

       хотя комментарий той же функции обещает «не пытается грузить модель на
       узле, где её нет». Живая последовательность: прогретая копия занята, рядом
       свободный узел с 8 ГБ, файла там нет → выбор падал на него, загрузка
       возвращала `model_not_found`, клиент получал 503, хотя достаточно было
       подождать слот готовой копии. То есть узел исключался не «каталогом», а
       отсутствием проверки каталога — молчаливым отказом в другую сторону.
     - **Стало:** в цикле выбора добавлена проверка каталога (R91-семантика,
       те же три состояния: снимка нет / `dirError` / файла нет); исключение
       только когда снимок прочитан и каталог узла не сломан. Узлы без снимка не
