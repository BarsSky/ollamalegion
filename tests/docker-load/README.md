# tests/docker-load — нагрузочные прогоны против живого стенда

Здесь лежат сценарии, которые **ходят по HTTP в поднятый стенд** и меряют
поведение под нагрузкой: очередь, параллелизм, удержание keep-alive,
распределение по бэкендам. Стенд должен быть уже запущен — сами скрипты ничего не
поднимают.

```bash
# стенд (канонический файл — stack.yml)
cd deployments && docker compose -f docker-compose.stack.yml --profile full up -d
```

## ⚠️ Адреса зашиты константами — сверьте их перед прогоном

Флагов командной строки у скриптов нет (argparse не используется), адреса заданы
константами в первых строках файла. Часть из них отстала от текущей раскладки
портов, поэтому **перед прогоном откройте файл и поправьте константы**:

| Скрипт | Константа | Значение в файле | Актуально? |
|---|---|---|---|
| `test_queue_realtime.py` | `BALANCER_PROXY` / `BALANCER_API` | `localhost:18080` / `:18081` | да |
| `test_queue_realtime.py` | `WEBUI_URL` | `localhost:18030` | нет, WebUI на `:18083` |
| `load_test_comprehensive.py`, `load_test_extended.py`, `test_queue_display.py` | `BALANCER_PROXY` / `BALANCER_API` | `localhost:18090` / `:18091` | нет, это старая раскладка; сейчас `:18080` / `:18081` |

Порты текущего стенда: `18079` OpenAI, `18080` Ollama API, `18081` admin API
(см. таблицу в корневом README).

## Куда попадают результаты

Все скрипты пишут в `results/` рядом с собой (`RESULTS_DIR` в начале файла) и
создают каталог сами, если его нет.

| Что | Формат | В git? |
|---|---|---|
| `results_*.json`, `results_extended_*.json`, `queue_realtime_*.json`, `queue_test_*.json` | сырые дампы: каждый запрос, тайминги, коды ответа | **нет** — правило `tests/docker-load/results/*.json` в `.gitignore` |
| `report_*.md`, `report_extended_*.md` | человекочитаемая сводка прогона | да, коммитится осознанно |

Сырые дампы исключены из git в 0.7.40: это были 13 файлов на 4.8 MB выходных
данных, на которые не ссылался ни один файл репозитория. Дамп остаётся на диске
рядом с отчётом — в коммит идёт отчёт.
