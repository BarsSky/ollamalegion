# Вход в WebUI: где он живёт и что нужно на новой машине

Дата: 2026-10-22 (R222). Относится к образам `webui` и `balancer`.

## Коротко

**Аутентификация живёт в балансере, а не в образе `webui`.** Образ `webui` — это nginx
со статикой: он отдаёт `index.html`/`js`/`css` и проксирует `location /api/` на
`API_HOST:API_PORT` (по умолчанию `loadbalancer:18081`). Поэтому перенос одного только
образа `webui` на другую машину не даёт ни экрана входа, ни ролей: запросы
`/api/v1/auth/*` просто некому обслуживать.

С R222 страница **больше не несёт в себе API-токен**: браузер работает через сессию
(cookie `ol_session` + `X-CSRF-Token`), а аварийный вход по токену оператор вводит сам.

## Что нужно, чтобы вход появился

1. **Балансер рядом и достижим** из контейнера `webui`:
   `API_HOST`/`API_PORT` (или compose-сеть, где балансер называется `loadbalancer`).
2. **Пользователи заданы на балансере** — любым из двух способов:
   - env `LB_ADMIN_USER` + `LB_ADMIN_PASSWORD`: при старте создаётся
     `LB_USERS_FILE` (по умолчанию `/app/data/users.json`) с одним администратором;
   - готовый файл `users.json` в смонтированном каталоге (пароли — только хеши
     PBKDF2-HMAC-SHA256; руками файл не пишут — его создаёт балансер из
     `LB_ADMIN_USER`/`LB_ADMIN_PASSWORD`, а потом правит раздел «Пользователи»).
3. **Том на `/app/data`** балансера (`balancer_data` в compose): без него `users.json`
   исчезнет при пересоздании контейнера.
4. **`deployments/.env` в образ не входит** — на новой машине переменные надо задать
   заново (`--env-file`, `-e` или свой `.env`).

Пример для одной машины (без compose):

```bash
docker network create ol-net

docker run -d --name balancer --network ol-net \
  -e LB_API_TOKEN='<токен стека>' \
  -e LB_ADMIN_USER=admin -e LB_ADMIN_PASSWORD='<пароль>' \
  -e LB_USERS_FILE=/app/data/users.json \
  -v balancer_data:/app/data \
  -p 18080:18080 -p 18081:18081 \
  ollama-legion/balancer:<тег>

docker run -d --name webui --network ol-net \
  -e API_HOST=balancer -e API_PORT=18081 \
  -p 18083:80 \
  ollama-legion/webui:<тег>
```

## ГДЕ ЛЕЖИТ users.json (частая причина «файла нет»)

Файл создаёт **балансер**, а не `webui`. Путь — `LB_USERS_FILE`:

| Как запущено | Путь | Виден на хосте? |
|---|---|---|
| compose-стек (`deployments/.env`) | `/app/data/users.json` (том `balancer_data`) | тома Docker, не каталог репозитория |
| `docker run` без `LB_USERS_FILE` | `config/users.json` **внутри контейнера** (`/app/config/...`) | нет: файл ефемерный, пропадёт при пересоздании |

Поэтому «в папке `config` репозитория нет `users.json`» — ожидаемое состояние:
в compose-стеке файла там и не будет. Проверять надо в контейнере:

```bash
docker exec <balancer> sh -c 'printenv LB_USERS_FILE; ls -l /app/data /app/config 2>&1'
docker logs <balancer> 2>&1 | grep -i 'auth:'
# ожидается: "auth: WebUI-вход включён ... users_file=/app/data/users.json users=1"
# или:       "auth: пользователей нет — вход в WebUI недоступен ..."
```

## ЕСЛИ ВХОД НЕ ПОЯВИЛСЯ (разбор по порядку)

1. **env задан не тому контейнеру.** `LB_ADMIN_USER`/`LB_ADMIN_PASSWORD` читает
   ТОЛЬКО балансер. У образа `webui` их нет вовсе — он nginx со статикой.
   `docker inspect <balancer> --format '{{range .Config.Env}}{{println .}}{{end}}'
   | findstr LB_ADMIN` должен показать обе переменные.
2. **контейнер перезапущен, а не пересоздан.** `docker compose restart` НЕ
   перечитывает `.env`: новый env попадёт в контейнер только при пересоздании —
   `docker compose up -d --force-recreate <балансер>`.
3. **запущен только webui** (без балансера рядом): `/api/v1/auth/*` обслуживать
   некому — экран входа есть (это статика), войти нельзя.
4. **старый образ балансера** (до R201): обработчиков `/api/v1/auth/*` нет,
   файл пользователей не создаётся ни при каких env.
5. **ошибка записи файла.** Если `LB_USERS_FILE` указывает на несмонтированный
   или недоступный путь, балансер писал WARN «администратор создан в ПАМЯТИ, но
   файл users.json не записан» (R229) — вход работает до пересоздания, потом
   пропадает. Лечение: `LB_USERS_FILE=/app/data/users.json` + том на `/app/data`.

6. **webui отвечает 503 на `/api/v1/auth/me`, а балансер напрямую — 200.** Так было
   до R229: `location /api/` (и `/api/v1/events|image|gguf`, `/ws/`) держали
   СТАТИЧЕСКИЙ `proxy_pass` на имя балансера, и nginx запоминал IP при своём старте.
   После пересоздания балансера (`up -d`) IP менялся — панель ходила на старый и
   отдавала 503, пока не перезапустят webui. Исправлено: upstream — переменная с
   `resolver 127.0.0.11` (правка в `webui/nginx.conf`, образ webui R229+).
   Проверка: пересоздайте балансер, НЕ трогая webui, и повторите `/api/v1/auth/me`
   через панель — должно стать 200 в пределах ~30 c.

Диагностика одной командой: `pwsh -File scripts/diagnose-webui-auth.ps1` (Windows) или
`sh scripts/diagnose-webui-auth.sh` (Linux/офлайн). Оба скрипта только читают: проверяют
env балансера, путь и наличие `users.json`, `/api/v1/auth/me`, длину и отпечаток
пароля в `.env` и в контейнере (сам пароль не печатается), а также реальный
`POST /api/v1/auth/login`. Ожидаемый ответ `/api/v1/auth/me`:
`{"authenticated":false,"usersConfigured":true}`. `usersConfigured:false` = пользователей
нет (см. пункты 1–2).

## ПАРОЛЬ ИЗ .env НЕ ПОДХОДИТ (401 invalid credentials)

Симптом: пользователи в env заданы, форма входа есть, но пароль не принимается, а
аварийный токен работает. Порядок проверки:

- сравните отпечатки: doctor печатает длину и `sha256[:8]` значения в `.env` и в
  контейнере балансера; расхождение означает, что значение искажено при передаче;
- спецсимволы в `.env`: `$` раскрывается compose как переменная (экранируйте как
  `$$`), `#` после пробела начинает комментарий, кавычки и хвостовые пробелы
  сохраняются буквально - всё это меняет пароль в контейнере;
- после любой правки `.env` нужен `docker compose up -d --force-recreate <балансер>`:
  `restart` env не перечитывает, в контейнере остаётся прежнее значение;
- отпечатки совпали, но вход 401: в `users.json` другой хеш - пересоздайте балансер
  (R203+ синхронизирует пароль из env при старте), образ старше R203 этого не делает;
- 503 `no users configured` = env не на балансере или образ старше R201; если
  напрямую 200, а через панель 503 - образ webui старше R229 (nginx держал IP балансера).

Практический итог: если doctor показывает совпадение отпечатков и HTTP 200 на шаге 4,
а браузер всё равно не пускает - проблема не в пароле, а в куке/сохранённом токене
этого хоста.

## Чек-лист проверки (curl)

```bash
# 1. вход настроен?
curl -s http://host:18081/api/v1/auth/me
# {"authenticated":false,"usersConfigured":true}

# 2. вход по паролю → cookie + csrf
curl -si -X POST http://host:18081/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"name":"admin","password":"<пароль>"}' -c cookie.txt
# Set-Cookie: ol_session=...; HttpOnly; SameSite=Lax
# {"success":true,"user":{"name":"admin","role":"admin"},"csrf":"..."}

# 3. чтение с сессией
curl -s -b cookie.txt http://host:18081/api/v1/models >/dev/null && echo read-ok

# 4. мутация без CSRF → 403, с CSRF → 200
curl -s -o /dev/null -w '%{http_code}\n' -b cookie.txt -X PUT \
  http://host:18081/api/v1/cppworker/model-profiles/probe -d '{}'
curl -s -o /dev/null -w '%{http_code}\n' -b cookie.txt -X PUT \
  -H 'X-CSRF-Token: <csrf>' \
  http://host:18081/api/v1/cppworker/model-profiles/probe -d '{}'
```

`usersConfigured:false` означает, что пользователей нет: панель покажет полосу
«вход не настроен» и предложит войти по токену. Это состояние исправляется первым
пунктом списка выше.

## Роли

| Роль | Что может |
|---|---|
| `admin` | всё: загрузка/выгрузка моделей, профили, настройки, бэкенды, пользователи |
| `viewer` («гость») | чтение и генерация; любые мутации сервер отклоняет (HTTP 403), админские контролы в UI скрыты |

Всё, что помечено в разметке `data-admin-only`, гость не видит; правило применяется и к
элементам, отрисованным позже (карточки моделей, таблицы), — за это отвечает
`MutationObserver` в `webui/js/modules/auth.js`.

Пользователями управляет раздел **Настройки → Пользователи** (R222). API тот же:
`GET/PUT/DELETE /api/v1/auth/users`. С R225 этот API доступен **только администратору** — включая
чтение: раньше viewer мог прочитать список пользователей с ролями.

**Активные сессии (R225).** В том же разделе — таблица входов: пользователь, роль, время входа и
последней активности, адрес и браузер, пометка «эта вкладка». Чужую сессию можно завершить кнопкой
(полный cookie-id не показывается никогда: наружу отдаётся короткий префикс, по нему же идёт
отзыв). API: `GET /api/v1/auth/sessions`, `DELETE /api/v1/auth/sessions?id=<8 символов>`.

**Политика пароля (R225).** Минимум 8 символов проверяется **на сервере** (`PUT /auth/users` →
400 «пароль короче 8 символов»), а не только в браузере.

## Аварийный вход по токену (break-glass)

Экран входа содержит поле «Аварийный вход по API-токену». Значение:

- проверяется запросом, который требует прав администратора (`GET /api/v1/auth/users`);
- хранится только в `sessionStorage` вкладки (закрыли вкладку — токена нет);
- подставляется в `window.WEBUI_CONFIG.API_TOKEN`, который читают модули;
- снимается кнопкой «Выйти» вместе с сессией.

Сам токен в отданную страницу больше не попадает — это и была дыра R201/R202: пока он
лежал в `config.js`, любой открывший панель действовал как администратор, а роль viewer
ничего не ограничивала.

## Ограничения

1. Сессии переживают рестарт балансера (R223): они лежат в `LB_SESSIONS_FILE`
   (по умолчанию `/app/data/sessions.json` — рядом с `users.json`, тот же том; права
   `0600`). Просроченные сессии при загрузке отбрасываются, `выход` и смена пароля
   убирают их из файла. Если переменная пуста — сессии живут только в памяти.
2. Несколько экземпляров балансера сессии не разделяют: файл читается при старте и
   пишется каждым процессом, общего хранилища нет.
3. Пока не вошли, страница не отправляет запросы к `/api/` вовсе: обёртка `fetch` в `auth.js`
   ждёт `/auth/me` и возвращает синтетический 401 без сети (R223). Раньше на экране входа
   висела пачка 401 в консоли и логах балансера.
4. Токен внешних клиентов (Cline, OpenWebUI) не связан с пользователями WebUI: это
   отдельный механизм (`X-API-Token`), он остаётся.
