# v0.7.238 — R479: паритет типов на `/v1` и `/ollama`

**Дата:** 2026-11-09 · **Тип:** исходники + образ балансера
**Образы:** balancer `r261109-2144` (`4f98d3fa`); cppworker и webui не менялись
(`gpu-261109-1754`, `r261109-1747`).

---

## 1. Что закрыто (P0 из `debts.ru.md`)

| Долг | Было | Стало |
|---|---|---|
| `/v1/*` недостижим для Ollama | диспетчер оставлял только `LlamaCppRouter`, тот фильтровал пул по типу → `503 no llama.cpp backend available` | если под модель нет cppworker-бэкенда, запрос уходит в Ollama нативно (тот же путь, тело, формат), слот занимается штатно, поток пишется с Flush |
| `/ollama/*` понимал только `LlamaCppRouter` | на Ollama-only кластере `/ollama/api/tags` пуст, `/ollama/api/chat` → 503 | алиасы `/ollama/api/*`, `/ollama/v1/*`, `/openai/v1/*` снимаются в начале `ServeHTTP`, ответ несёт `X-LB-Surface-Alias: 1` |
| `/v1/models` без Ollama | список собирался только из cppworker-источников | добавлены running models из метрик и `/api/tags` каждого Ollama-бэкенда |

Ограничение passthrough: только пути, которые Ollama умеет нативно
(`/v1/chat/completions`, `/v1/completions`, `/v1/embeddings`, `/v1/models`).
`/v1/messages` и `/v1/responses` остаются прежним кодом — у них другой формат,
и «как есть» в Ollama вернуло бы ошибку.

## 2. Что закрыто из P1

- **Лимит тела на generic-пути:** `LB_MAX_REQUEST_BODY_MB` проверяется в
  `parseRequestBody` (413 без отправки бэкенду); `extractModel` и
  `recordRecentClient` читают только начало тела и возвращают остаток в поток —
  без второй копии запроса в памяти.
- **Стадии:** добавлены `preflight`, `client_write`, в строке `request trace`
  появился `stage_final` (`done` — успех без обрыва).
- **Обрыв доставки:** `MarkAbortR477` пишет в кольцо сбоев причину обрыва даже
  при статусе 200 — «токены шли, ответ не дошёл» больше не выглядит успехом.

## 3. Проверено (живые числа)

- `/api/tags` → 200, 3 модели.

  Ollama-only кластере — пусто; здесь кластер cppworker-only, поэтому проверено
  на паритет путей, а не на другом типе).
