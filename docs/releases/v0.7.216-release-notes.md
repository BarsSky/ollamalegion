# OllamaLegion v0.7.216 - release notes

A source release after `v0.7.211` (v1.0-rc2). It closes four themes: a WebUI showcase that
needs no stand, a documentation refactor, full localisation of logs and errors, and the gates
that keep all of it from regressing.

## What is inside

| Round | What was done |
|---|---|
| R232 | **WebUI demo mode** (`WEBUI_DEMO_MODE`, env only): a guest sees a deterministic scenario "clients -> balancer -> queue -> RPC donor -> AutoTune"; all `/api/`, WebSocket and SSE traffic is intercepted in the browser, mutations return `403`. |
| R233 | **Documentation: one structure.** 46 files were moved out of the `docs/` root into categories, byte-identical duplicates and untranslated copies were removed, `plans/` moved to `docs/plans/`, history to `docs/archive/`. A single index at `docs/README.md` + `README.ru.md`. |
| R233 | **Full documentation localisation:** 38 EN/RU pairs, older English versions brought to parity with the Russian source, every link rewritten (564 links, 0 broken). |
| R234 | **Log and error language** - a stand setting: the `internal/i18n` catalog, priority `flag > env > config > locale`, the balancer serves the language (`GET/PUT /api/v1/i18n`, `logLanguage` in the cluster config), workers sync with it without a restart, a switcher in the WebUI settings. |
| R235 | **Localisation content:** 734 keys, 749 places in 115 Go files, the scanner widened (zap logs, JSON `error/hint/note`, CLI usage), the untranslated budget is 0. |
| R236 | **CI gates + live verification:** `run-checks` now runs `i18n-scan`, `verify-doc-pairs`, `verify-docs-complete` and the `internal/i18n` package; on a live stand we checked the `en` start, the switch through the API and the WebUI, and worker sync (~7 s). |

## Images

This release updates **balancer** and **webui** (verified locally as `balancer:r236-i18n`,
`webui:r236-i18n`). `cppworker`, `agent` and `sdworker` must be rebuilt so they include the
language sync code:

```bash
pwsh -File scripts/build-containers.ps1 -Balancer -WebUI -Agent -CppWorker -Tag r236
docker compose -f deployments/docker-compose.stack.yml --profile full up -d --force-recreate
```

`sdworker` is built through compose (`--profile full build imageworker`); the current
`imageworker:cuda-75-86-120` does not contain the R234 code yet.

## How to enable the log language

```dotenv
# deployments/.env
OLLAMALEGION_LOG_LANG=en          # ru | en | auto
OLLAMALEGION_LOG_LANG_SYNC_SEC=60 # how often workers ask the balancer
```

or in the WebUI: "Settings -> Log and error language -> Apply" (administrator). The switch
works without restarting containers.

## Upgrading from v0.7.211

1. `git pull` (branch `centurion`), then `git submodule update --init --recursive`.
2. Rebuild the images (see above) and recreate the containers.
3. No config change is required: `logging.language` is optional, without it the language comes
   from the locale and falls back to `ru`, i.e. the previous behaviour is preserved.
4. Documentation: the old paths (`docs/api.md`, `docs/en/...`, `docs/ru/...`, `plans/...`) no
   longer exist - start from `docs/README.md`.

## Known limitations

- The localisation intentionally does not translate: code comments, prompts sent **to the
  model**, marker strings used to match foreign text, and fact strings produced by external
  programs (llama.cpp, sd-server). The list and the reasons are in
  `docs/development/i18n-logs.md`.
- A language switch applies to new messages; strings already written stay in the previous
  language.
- Test flakes observed in this session: one network test in `internal/balancer` and
  `TestHFBundle_FileProgressShape` on Windows (TempDir cleanup) - green on re-run, fixing them
  is a separate task.
