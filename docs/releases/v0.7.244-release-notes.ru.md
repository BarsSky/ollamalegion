## 1. Зачем

В коде было три предиката «это стрим?», и они расходились в ДЕФОЛТЕ для запроса
без поля `stream`:

| Где | Дефолт без `stream` |
|---|---|
| `parseRequestBody` (proxy.go) | legacy-поверхность — **true**, OpenAI — false |
| `isStreamingRequest` (proxy_request.go) | **true** |
| `isStreamingFromBody` (llamacpp_translate_req.go) | **false** |

Следствие (живой случай R480 с BOM в теле): `/api/chat` без явного `stream`
считался стримовым при выборе очереди/окна, но транспорт llama.cpp уходил в
non-stream; в лог при этом писалось `stream=true`, и оператор искал «почему не
стримится» не там. Ровно та же ложь мешала разбирать «ответ одним куском» на
27B-стенде.

## 2. Что сделано

### 2.1. Один разбор поля `stream`

`stream_flag_r484.go`:

```go
streamFlagFromBodyR484(body, defaultWhenAbsent) (stream, explicit, ok)
streamDefaultForSurfaceR484(surface) bool
```

Все три пути вызывают один разбор; **различия в дефолте передаются явно** и
покрыты тестом. Поведение не изменено: legacy стримит по умолчанию, OpenAI —
нет, транспорт llama.cpp — только по явному `stream:true`.

### 2.2. `transport` в диагностике

Трекер в контексте (как stage R477) выставляется транспортными функциями:

| `transport` | Что было на самом деле |
|---|---|
| `stream` | потоковый транспорт (NDJSON/SSE, запись по чанкам) |
| `json` | ответ прочитан и отдан целиком |

Поле есть в строке `request trace` и в записи `/api/v1/proxy/logs`
(`transport`). Теперь `stream=true` + `transport=json` — видимая норма для
legacy-запроса без `stream`, а не «балансер сломал стриминг».
