11a. **Причины отказа по КАЖДОМУ кандидату в `why_queued`.** **ЗАКРЫТО

    - `vram_insufficient` — «модель не влезает: need 12.6 GiB, free 5.9 GiB»:
      та же арифметика, что решает выбор узла под загрузку (R248/R493: размер

      селектор и очередь: раньше в `why_queued` было «заняты все слоты (1/4)» на
      узле, который физически принимает один запрос (статический лимит конфига 4,
      заявка узла 1). Числа в причине были неверными — то есть дефект был не в
      отсутствии причины, а в её содержимом.

    (в причине «(1/1)», а не «(1/4)»); мутации «убрать причину VRAM» и «считать
    слоты по статике» роняют тесты.

11b. **Каталог моделей узла молча исключает узел.** **ОТКРЫТО, нужна проверка на
    стенде.** `expandCandidates` отправляет узел в P3 только если модель есть в
    метриках/каталоге; если файл на диске есть, а `/api/tags` узла его не
    показывает, узел выпадает из выбора БЕЗ причины (путь R91
    `model_catalog`). Оператор утверждает, что файл лежит всегда — значит либо
    каталог не обновляется, либо модель называется иначе. Проверка:
    `curl -s http://<узел>:18092/api/tags | jq -r '.models[].name'` на каждом
    узле; до подтверждения правку не делаем (иначе «починка» вслепую).
