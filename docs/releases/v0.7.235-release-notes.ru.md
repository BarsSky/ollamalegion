# v0.7.235 — R448…R473: окно контекста перестало быть догадкой

**Дата:** 2026-11-07 · **Тип:** исходники + образы стенда
**Образы:** balancer `r261106-2329` (`f306aa48`), cppworker `gpu-r261106-2122`
(`5a97880d`), webui `r261106-1716`. Манифест: `deployments/release-manifest.json`.

---

## 1. Коротко

Этот выпуск закрывает один класс дефектов агентского цикла: **решения об окне
контекста принимались по нашей же догадке**. Оценка промпта (эвристика по
символам) завышала в 1.8–5 раз, из неё рождались отказы 413, отменённый рост
окна, ложные тексты клиенту и перезагрузки модели на окно больше нужного.

Теперь: оценку заменяет **токенизатор самой модели**, отказ по физике остаётся
только для окна, которое клиент запросил сам, а рост окна больше не блокируется
хинтом профиля.

| Что было | Живой факт | Чем закрыто |
|---|---|---|
| 413 «требуется 151743 на окно» при занятых 63.6k | оценка 151743 против реальных 63.6k | **R466**: 413 только для окна, запрошенного клиентом; выведенное окно урезается до потолка и грузится |
| сессию увели на копию с меньшим окном (65536 → 32768) и ход сломался | ребалансировка смотрела только на загрузку | **R459**: переезд запрещён, если кандидат даёт меньше окна (и на холодную копию — тоже) |
| «свободный бэкенд, а запрос в очереди» — объяснить нечем | в логе одна строка `admission: request queued` | **R460**: причина по каждому бэкенду в логе и в теле 503 |
| «модель сгенерировала только размышления, увеличьте max_tokens» при окне 131072 | текст утверждал исчерпание бюджета всегда | **R461**: «исчерпан (X из Y)» / «не исчерпан, модель остановилась сама» |
| `num_predict` в env есть, в WebUI его нет | поля не доезжали через структуру балансера | **R463–R465**: бюджет в API и чип в WebUI |
| клиент получил 503 «нужно 39542» при своих 20.7k | 39542 = наша оценка 36601 + бюджет | **R473**: точный подсчёт токенизатором (`POST /api/tokenize`), 36601 → 10036 |
| рост окна отменялся «потолком 32768» при операторском 65536 | `WindowFeasibility` считал потолком `contextLength` профиля (хинт загрузки) | **R472**: потолок = min(GGUF, `contextLengthMax`, `LB_NCTX_RELOAD_MAX_N_CTX`); причина отказа теперь WARN |
| Cline видел в одном поле рассуждение + ответ | клиент складывает `message.thinking` в текст ответа | **R470/R471**: размышления не навязываются, если клиент не просил `think`; начало вывода не утекает в `content` |
| «вызов не выполнен: нераспознанный формат» при валидном вызове | вызов распознан, но инструмент не объявлен (Plan mode) | **R468**: текст называет настоящую причину и объявленный набор |

## 2. Как проверялось (живые числа, не пересказ)

- **R466**: `R466 выведенное окно урезано до потолка` → `async reload succeeded new_n_ctx=65536`
  за 48 с; повторный тот же запрос решений о росте не даёт.
- **R472**: `503 «started reloading … retry in 60»` → модель загружена `context_size=40704`
  за 40 с → повтор **200** с полным ответом (250 КБ NDJSON).
- **R473**: один и тот же запрос — `estimated_tokens: 36601` → `exact_tokens: 10036`,
  перезагрузка не потребовалась; один HTTP-вызов токенизатора на уникальный текст
  (кэш + single-flight).
- **R468**: `reason=call_undeclared, dropped_tool_names={write_file}` и текст
  «инструмент не объявлен (объявлены: read_files)» вместо «нераспознанный формат».
- **R461**: обе ветки живьём — «бюджет исчерпан (32 из 32)» и «не исчерпан (21 из 2048),
  модель остановилась сама».
- **R470/R471**: `thinking_chunks=0` без `think`; с `think:true` — 90 чанков (просьбу уважаем).

## 3. Что появилось нового

- `POST /api/tokenize` (cppworker, R467): точный подсчёт токенов токенизатором модели;
  `source=tokenizer|estimate` — честно называет, чем посчитано.
- `GET /api/v1/cppworker/config[/runtime]`: политика бюджета вывода
  (`outputBudget`: потолок 16384, reasoning 8192) и `default_num_predict` на модель.
- WebUI «Загруженные»: чип `num_predict` + заголовки `X-Model-Max-Context`
  (действующий потолок) и `X-Model-Gguf-Max-Context` (сырой GGUF).
- Тумблеры: `CPPWORKER_TOOLS_THINKING` (`auto|on|off`), `LB_PREFLIGHT_EXACT_TOKENS`
  (по умолчанию **вкл**), `CPPWORKER_MAX_N_PREDICT` (16384).
