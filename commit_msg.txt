feat(balancer): R60.22 — proper duration metrics + tokens_per_second in done chunk

User reported: OpenWebUI shows "N/A" for response_token/s, prompt_t/s,
prompt_eval_duration=0, eval_duration=0 (only total_duration is real).

Root cause: balancer never tracked Time-To-First-Token (TTFT). The
usage chunk from cppworker only has token counts, not duration breakdown.
So balancer had to compute prompt_eval_duration and eval_duration itself
from streamStart and... nothing else. Both fields ended up as 0.

R60.22 fix: track firstContentTime when first non-empty content delta
arrives. Then split total_duration:
  prompt_eval_duration = firstContentTime - streamStart  (TTFT)
  eval_duration         = total_duration - prompt_eval_duration

Plus: added tokens_per_second (eval_count / eval_duration) so OpenWebUI
shows real token/s rate instead of "N/A".
