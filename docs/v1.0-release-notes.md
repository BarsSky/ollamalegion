# OllamaLegion v1.0 — релиз исходников

**Дата:** 2026-09-27 · **Тип:** source-only (без бинарников и Docker-образов)
**Что это:** исходный код всего проекта + краткое описание того, что реально
работает, что работает частично и что стоит заглушкой.

---

## 1. Что это за проект

Балансировщик нагрузки и оркестратор для inference на **llama.cpp** (плюс
Ollama-совместимые бэкенды) с адаптивной загрузкой моделей: система сама решает,
сколько слоёв модели уедет на GPU, какой `n_ctx` поместится, и что делать, если
не помещается ничего.

Клиенты (OpenWebUI, Cline, anything-llm, curl) говорят с **одним** адресом —
балансером — и не знают, на какой машине и с какими параметрами реально
загрузится модель.

```
клиент ──► balancer :18080 (OpenAI + Ollama API)   :18081 (admin API)
              │
              ├── agent :18032 ── метрики узла (GPU/RAM/CPU) в балансер
              └── cppworker :18092 ── llama.cpp (CGo), загрузка GGUF, стриминг
                    └── webui :8080 ── дашборд оператора (наш, не OpenWebUI)
```

## 2. Что реально работает (проверено на живом стенде)

| Область | Что сделано |
|---|---|
| **Инференс llama.cpp** | `/api/chat`, `/api/generate`, `/v1/chat/completions`, `/v1/completions`, `/api/embeddings`; стриминг NDJSON и SSE; tool calls (нативные + 7 текстовых форматов); reasoning/thinking |
| **Ollama-совместимость** | `/api/tags`, `/api/show`, `/api/copy`, `/api/create`, `/api/pull` (`hf:`-источники), `/api/ps`, `/api/delete`; `keep_alive` |
| **Память и раскладка** | Единый решатель `internal/memfit` (одна формула KV-cache, типизированные байты, честное «неизвестно»); потолки n_ctx, отказ 422 вместо попытки грузить невозможное; честные поля режима (`n_ctx_degraded`, `max_exact_fit_n_ctx`) |
| **Загрузка моделей** | Асинхронная (202 + `progressUrl`), дедупликация по пути, single-flight, защита от двойной загрузки; reload с rollback при провале; авто-выгрузка простаивающих |
| **Очередь и справедливость** | Единая admission-очередь слотов, `X-Queue-Position`/`X-Queue-Wait-Ms`, keepalive для ждущих streaming-клиентов, per-session справедливость, различение пользователей OpenWebUI |
| **Placement (мультибэкенд)** | Политика по модели/классу: `single`, `pool`, `replicated`, `auto` (выбор по VRAM-fit); «не уходить в другую стратегию молча» (503 либо `X-LB-Placement-Fallback`); группы репликации, усыновление уже загруженных копий, failover запроса на живую копию |
| **Наблюдаемость** | `/api/v1/metrics`, `/api/v1/health`, `/api/v1/health/detailed` (recentErrors из SSE-буфера), `/api/v1/queue/stats`, `/api/v1/placement`, dashboard `/monitor`, уведомления о провалах загрузки и о деградации |
| **Эксплуатация** | Релизные скрипты с манифестом тегов, проверка согласованности compose ↔ `.env`, hardware-пресеты для RTX 30xx/40xx/50xx и A10, живые верификаторы инвариантов |

**Объём:** 457 тестовых файлов в 27 пакетах; ключевые наборы — `balancer` (172),
`cppworker` (88), `api` (42), `cppbackend` (33).

## 3. Что работает частично

| Фича | Состояние | Как выглядит для клиента |
|---|---|---|
| `sharded` (tensor parallelism) | **этап P2, не исполняется** — ждёт выбора транспорта (llama.cpp RPC vs B8.7) | 503 с причиной и блоком `placement`, либо `single` + `X-LB-Placement-Fallback` при `fallback=single`. В `/api/v1/placement` в списке `executable` их **нет** — видно машиночитаемо |
| `rpc` (распределённый inference) | **этап P2, не исполняется** — тот же выбор транспорта | то же |
| RPC coordinator | работает, но **токены в метриках = 0** (`TODO (Phase 9)`) | статистика токенов для rpc-режима неполная |
| Batched scheduler | работает, но **не умеет отменять** генерацию (`TODO R63.x`) | abort не прерывает батч мгновенно |
| Ollama registry (`/api/pull` по имени без `/`, `/api/push`) | **сознательная заглушка** | честный 501 с подсказкой: используйте `hf:<repo>/<file.gguf>` или `/api/hf/download` |
| Безопасность (mTLS, тонкий rate limiting, audit) | базовая (токены, CORS, лимиты) | в backlog post-1.0 |
| `stub`-сборка (`-tags llama_stub`) | **заглушка намеренная** — для CI без GPU | инференса нет, всё остальное (API, загрузка, метрики) работает |

## 4. Что стоит заглушкой (сознательно, post-1.0)

- **Pipeline parallelism** — не реализовано.
- **Expert parallelism для MoE** — не реализовано.
- **Continuous batching** — не реализовано (есть динамический выбор `n_parallel`).
- **Real ggml/NCCL tensor parallelism** — research-grade (`docs/phase-8-p3-research.md`).

Все четыре **не обещают работы**: они либо отсутствуют в API, либо (для
placement) честно помечены как неисполнимые в `/api/v1/placement`.

## 5. Что нужно для финального тега v1.0

Остался один шаг, который требует железа (A10 24 GB или аналог) и не может быть
сделан в CI:

- **ручной smoke-прогон** по `docs/v1.0-smoke-checklist.md` — 12 сценариев
  (загрузка, стриминг, tools, контекст, очередь, репликация, failover,
  уведомления);
- после него — тег `v1.0` (сейчас релиз исходников помечен `v1.0-rc2-src`).

## 6. С чего начать

### 6.1. Что нужно до первой сборки

- **Go 1.21+** — для балансера, cppworker (Go-часть), агента, WebUI-сервера.
- **Сабмодуль `llama.cpp`.** В архиве исходников каталог `c/llama.cpp` **пуст**:
  это git-сабмодуль (`https://github.com/ggml-org/llama.cpp.git`, ветка `master`),
  а `git archive` содержимое сабмодулей не переносит. Инициализируйте его:

  ```bash
  git clone https://github.com/BarsSky/ollamalegion.git && cd ollamalegion
  git submodule update --init --recursive c/llama.cpp
  ```

  Если вы распаковали архив — положите чекаут llama.cpp в `c/llama.cpp` вручную.
  Без него собирается **только `-tags llama_stub`** (заглушка без инференса): этого
  достаточно, чтобы прогнать все тесты и проверить код.
- **C-тулчейн** (MSVC либо GCC/CMake) — нужен только для настоящей сборки
  cppworker с CPU/CUDA-инференсом.
- **`.env`.** Рабочих файлов окружения в архиве нет — и это намеренно (в них
  токены). Берите шаблоны: `config/cppworker.example.env`,
  `config/agent.example.env`, `deployments/.env.bundled-with-agent`.

### 6.2. Порядок действий

```bash
# 1. Прочитать: docs/installation.md, docs/configuration.md, docs/ENV_VARS.md
# 2. Выбрать пресет под железо:
python scripts/apply-hardware-preset.py <preset>   # см. docs/ru/hardware-presets.md
# 3. Проверить код и тесты без CGo:
go build -tags llama_stub ./...
go test  -tags llama_stub ./...
# 4. Продовый стек: deployments/docker-compose.cppworker-bundled-with-agent.yml
```
