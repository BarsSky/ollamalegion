# R297 (кандидат): «загрузка модели» отвечает HTTP 200, а провал виден только в логе

**Статус: НЕ ЧИНИЛОСЬ. Записано по требованию оператора («не чинить, но записать
file:line»), воспроизведение на стенде не выполнено.**

## Живой факт (стенд оператора)

Операторская (WebUI/API) загрузка модели ответила **HTTP 200 за ~0.01 с**, при этом
в логе балансера через некоторое время появилось:

```
executeLlamaCppLoad: model never appeared in cppworker list/progress, stop polling
```

То есть клиенту сообщили «загружено», а фактически загрузки не было. Класс дефекта:
**подтверждение успеха без подтверждения факта** — тот же, что R262 (таймаут ≠
провал) и R296 (начало операции ≠ выгрузка), только в обратную сторону.

## file:line (что именно участвует)

| Роль | Место |
| --- | --- |
| HTTP-статус успеха | `internal/api/handlers_model_management.go:232-233` — `modelOpStatusCode`: `result.Success == true` ⇒ 200 |
| Решение «успех» без подтверждения | `internal/balancer/model_management.go:1693-1701` — fall-through: `status=already_loaded / loaded / loaded_by_other / **unknown**` ⇒ `ModelOpResult{Success: true}` |
| Фактический провал (только лог) | `internal/balancer/model_management.go:1126-1142`, лог на `:1129` — «model never appeared in cppworker list/progress, stop polling» |
| Отдельный путь 202 | `internal/balancer/model_management.go:1684-1691` — «async load (202): model not found after maxWait» |
| Индикатор «ещё грузится» | `internal/balancer/model_management.go:171-179` (`StillLoading`) + `internal/api/handlers_model_management.go:242-244` (202) |

## Гипотеза причины (НЕ доказана)

`/api/models/load` у cppworker может ответить телом, которое балансер не смог
разобрать (или без поля `status`) — тогда ветка `unknown` на `model_management.go:1693`
трактует это как успех и отдаёт `Success: true`, а наблюдатель (поллинг) в этот момент
ещё не подтвердил появление модели. Симметрично: 0.01 с — это время одного
HTTP-обмена с воркером, что исключает любой путь с поллингом.

## Что нужно, чтобы доказать и починить

1. На стенде повторить загрузку и снять **сырое тело** ответа cppworker на
   `POST /api/models/load` (в логе балансера оно сейчас не печатается).
2. Убрать `unknown` из списка «успех»: считать успехом только явные
   `loaded` / `already_loaded` / `loaded_by_other`; `unknown` ⇒ `StillLoading`
   (202 + reason) или честная ошибка с текстом тела.
3. В ответ 200 добавить признак подтверждения (`confirmed: true` только когда модель
   реально видна в `/api/models` или в `/api/models/loaded` воркера).
4. Тест: `unknown`-тело не даёт `Success: true`; HTTP-статус при `unknown` — 202.

## Почему не сейчас

Правка меняет контракт ответа «загрузить модель» и требует живого стенда для
проверки (без воркера любые утверждения о телах — догадки). R296 закрывает
подтверждённые живые дефекты (ложная причина обрыва + числа контекста), его и
доводим до стенда; R297 — следующая итерация.
