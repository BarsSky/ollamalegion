# v1.0 — чек-лист ручного smoke на A10 24 GB

**Зачем:** единственный шаг перед финальным тегом `v1.0`, который нельзя сделать
в CI — проверить поведение на реальном железе с реальной моделью (A10 24 GB +
Qwen3-A3B / Qwen3.8-27B). Ниже — 12 сценариев; у каждого есть **ожидаемый
результат** и **как проверить**, без чтения кода.

**Подготовка (один раз):**

```powershell
# стек поднят
cd deployments
docker compose -f docker-compose.cppworker-bundled-with-agent.yml up -d
docker ps --format '{{.Names}}\t{{.Status}}' | Select-String ol-bundled

# адреса
$B = 'http://127.0.0.1:18080'          # балансер (клиентский API)
$A = 'http://127.0.0.1:18081'          # admin API
$T = 'changeme-bundled-with-agent-token'
```

Отмечайте `PASS`/`FAIL` в таблице в конце; для каждого FAIL полезно приложить
вывод команды — так разбор не потребует повторного прогона.

---

## 1. Загрузка модели и режим раскладки

```powershell
curl.exe -s -H "X-API-Token: $T" -H 'Content-Type: application/json' `
  -d '{"name":"qwen3.8:latest","contextSize":32768}' "$B/api/v1/gguf/backends/cppworker-gpu-bundled-agent/proxy/api/models/load"
# подождать state=loaded
curl.exe -s "$B/api/v1/cppworker/models" | Select-String 'n_ctx_degraded|max_exact_fit_n_ctx|gpu_layers'
```

**Ожидается:** модель `state=loaded`; `gpu_layers > 0` (не CPU-only);
`n_ctx_degraded` отражает реальность (при 32768 и потолке в десятки тысяч — `false`);
`max_exact_fit_n_ctx` присутствует. **Регресс:** `gpu_layers=0` или
`n_ctx_degraded=true` при небольшом контексте.

## 2. Стриминг ответа (Ollama API)

```powershell
curl.exe -s -N -H "X-API-Token: $T" -H 'Content-Type: application/json' `
  -d '{"model":"qwen3.8:latest","messages":[{"role":"user","content":"Reply with exactly: OK"}],"stream":true}' `
  "$B/api/chat" | Out-File .\chat.txt
```

**Ожидается:** ровно **один** кадр `"done":true`; в нём `message.content` пуст;
текст приходит только дельтами; есть `eval_count` и `prompt_eval_count`.
**Регресс:** два `done:true`; полный текст в `done` (клиенты, конкатенирующие
чанки, покажут ответ дважды).

## 3. OpenAI-совместимый путь

```powershell
curl.exe -s -N -H "X-API-Token: $T" -H 'Content-Type: application/json' `
  -d '{"model":"qwen3.8:latest","messages":[{"role":"user","content":"hi"}],"stream":true}' `
  "$B/v1/chat/completions" | Select-String 'delta|finish_reason|\[DONE\]'
```

**Ожидается:** в финальном кадре (`finish_reason` не пуст) `delta.content` пуст;
далее usage-кадр и `[DONE]`.

## 4. Tool calling (Cline-подобный запрос)

```powershell
# запрос с tools; проверить, что tool_call приходит объектом, а не строкой
curl.exe -s -H "X-API-Token: $T" -H 'Content-Type: application/json' --data-binary "@tools.json" `
  "$B/api/chat" | Select-String 'tool_calls|done_reason'
```

**Ожидается:** `done_reason: "tool_calls"`, `message.tool_calls[].function.arguments`
— **объект** (не JSON-строка), `content` пуст.

## 5. Контекст: запрос выше потолка

```powershell
curl.exe -s -o out.json -w "%{http_code}`n" -H "X-API-Token: $T" -H 'Content-Type: application/json' `
  -d '{"name":"qwen3.8:latest","contextSize":999999}' `
  "$B/api/v1/gguf/backends/cppworker-gpu-bundled-agent/proxy/api/models/load"
```

**Ожидается:** `422`, `code=n_ctx_infeasible`, в теле есть `max_viable_n_ctx` /
`hard_max_n_ctx` и внятная подсказка. **Регресс:** `202` и последующая попытка
грузить заведомо невозможное.

## 6. Контекст: запрос между отчётом и потолком

Повторить п.1 с `"contextSize":60000` (если потолок железа выше).

**Ожидается:** либо `202` и **успешная** загрузка (`state=loaded`, фактический
`context_size` = запрошенному), либо честный отказ с числами. Не ожидается:
«принято → повисло навсегда».
**Замер:** время до `state=loaded` (на 27B при 60000 — порядка 7–8 минут против
~2.5 при 32768; это нормальная цена большого контекста).

## 7. Очередь и справедливость

```powershell
# 4 одновременных запроса при вместимости 1
1..4 | ForEach-Object -Parallel {
  curl.exe -s -o "r$_.json" -w "%{http_code}`n" -H "X-API-Token: $T" -H 'Content-Type: application/json' `
    -d '{"model":"qwen3.8:latest","messages":[{"role":"user","content":"count to 20"}],"stream":false}' `
    "$using:B/api/chat"
}
curl.exe -s -H "X-API-Token: $T" "$A/api/v1/queue/stats" | Select-String 'admission|current_size'
```

**Ожидается:** все 4 — `200`; у трёх из четырёх в заголовках `X-Queue-Position`;
`admission.served > 0`. **Регресс:** `503` на занятых слотах.

## 8. Уведомление о провале загрузки

```powershell
curl.exe -s -o e.json -w "%{http_code}`n" -H "X-API-Token: $T" -H 'Content-Type: application/json' `
  -d '{"model":"v1-nonexistent:latest","messages":[{"role":"user","content":"hi"}],"stream":false}' "$B/api/chat"
Start-Sleep 15
curl.exe -s -H "X-API-Token: $T" "$A/api/v1/health/detailed" | Select-String 'recentErrors|v1-nonexistent'
```

**Ожидается:** не-2xx с причиной; событие в `recentErrors` **без открытого
SSE-клиента** (проверяет наполнение ring buffer).

## 9. Репликация и failover (нужны 2 cppworker)

См. `plans/2026-09-25-placement-p4-load-kpi.md` (стенд 2×cppworker).

**Ожидается:** `replication total=2 loaded=2`; при `docker stop` одной копии
запросы обслуживает живая (без 503); запрос, выбравший упавшую реплику,
переезжает за считанные секунды; восстановление 20–35 с.

## 10. Placement-политика: неисполнимые стратегии

```powershell
curl.exe -s -H "X-API-Token: $T" "$A/api/v1/placement" | Select-String 'executable|sharded|rpc'
```

**Ожидается:** в `executable` только `single/pool/replicated/auto`; при
`fallback=error` запрос с `sharded`/`rpc` получает `503` с причиной **до**
маршрутизации; при `fallback=single` — `200` + `X-LB-Placement-Fallback`.

## 11. Дашборд оператора

Открыть `http://127.0.0.1:8080/` и `/monitor`.

**Ожидается:** страницы рендерятся, в консоли браузера нет
`ReferenceError`/`fetchAll failed`; на `/monitor` видны бэкенды, ресурсы,
карточка размещения и admission-очереди; уведомления (bell) показывают провалы
и деградацию.

## 12. Отсутствие регрессий в логах

```powershell
docker logs --since 2h ol-bundled-cppworker-gpu 2>&1 | Select-String 'SIGABRT|unaligned tcache|panic|VRAM insufficient'
docker logs --since 2h ol-bundled-balancer     2>&1 | Select-String 'panic|fatal'
```

**Ожидается:** пусто.
