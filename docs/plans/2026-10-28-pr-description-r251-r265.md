## Что это

Набор из 19 коммитов (`R251–R265`), закрывающих класс дефектов, которые видны только на
длинных агентских сессиях (Cline, DSH/DeepSeek Harness, Roo Code): потеря сессии в панели,
обрыв на пороге контекста, буферизация не-стрим ответов, размышления в видимом ответе,
ложные «stream truncated», молчаливый пустой ответ и «ошибка загрузки» при загруженной модели.
Ключевой принцип правок: не менять поведение там, где оно верное, и не оставлять второго
источника истины для одного факта.

## Как проверялось

**Живьём на стенде** (`balancer:r264`, `webui:r264`, cppworker):

- сессия и монитор: одна сессия на 19 запросах, `createdAt` неизменен, `recentClients=1`;
- рост окна и дообслуживание: промпт ~12277 tok при окне 8192 → reload до 12501, ответ клиенту
  пришёл целиком, ровно один `[DONE]`;
- reasoning: `reasoning_chars=573`, `visible_chars=0`, кадр-объяснение перед `finish`;
- большой ответ: 404 723 байта / 84 с, без `stream truncated`, без error-кадров;
- не-стрим + `Accept: text/event-stream`: поток, один `[DONE]`; без Accept — прежний JSON;
- загрузка модели: 200 за 345.8 с с «polling confirmed completion»; без `backendId` — только
  здоровый узел, мёртвый в `skipped`; явный мёртвый — 503 за 0.44 с;
- флаг «загружено»: `loadedModelCount=1 total=2`, совпадает с `state` воркера;
- логи за прогон: `panic=0`, `error=0`, `stream truncated=0`, `token too long=0`.

**Только юнит-тестами:** правило переиспользования сессии при сжатии истории (все ветки условия),
политика `repairableToolArgsFragment`, `202 StillLoading`, вытеснение модели, согласование
`contextLength` / `contextPerSeq` для окна 256000, характеризационные тесты потолков `n_ctx`.

**Не проверено на живом стенде (ограничение железа, не кода):**

- ветка `202 StillLoading` — модель успевала загрузиться к концу окна ожидания
  (наблюдался путь «recovered from HTTP timeout»);
- вытеснение модели — на карте 8 ГБ cppworker держит обе модели (вторая уходит в CPU-offload),
  вытеснения не возникает; проверен инвариант «API == фактическое состояние»;
- окно 256000 из меню модели — на этой карте физически недостижимо.

Чек-лист для проверки этих пунктов на втором стенде: `docs/plans/2026-10-28-stand-checklist-2.md`.

## Риски и откат

- Изменено поведение reload модели: окно теперь может расти по оценке промпта (за флагом
  `LB_NCTX_GROW_FOR_AGENTS`). Откат поведения — одной переменной, без отката образа.
- Прочее — исправления без смены контрактов; `stream=false` без `Accept: text/event-stream`
  по-прежнему получает цельный JSON.
- Откат стенда: теги образов в `deployments/.env` (`BALANCER_TAG`/`WEBUI_TAG`) + резервные копии
  `.env.bak-before-r250 … .env.bak-before-r264`, затем
  `docker compose -f docker-compose.stack.yml up -d loadbalancer webui`.

## Остаточный тех-долг

1. `profileCapCtx(fold)`: preflight читает профиль по точному ключу, физический потолок — по
   терпимому (живой дефект R68). Перевод preflight на `fold` изменит пороги reload → нужен
   отдельный заход с прогоном на стенде (кандидат `R266`).
2. `resolveModelMaxContext` нельзя свести с физическим потолком до решения: профиль — это
   **кап** или **подсказка**? Сейчас зависит от `contextLengthAuto`.
3. `physicalCeiling` не проверяет, не устарел ли `PhysicalMaxContext` — это обязанность
   вызывающего кода; нужно либо задокументировать явно, либо добавить метку времени.
