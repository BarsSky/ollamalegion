# R309–R310: горячие настройки в панели и восстановление комментариев

Дата: 2026-10-30. Ветка: `centurion`. Предыдущий разбор: `2026-10-30-r306-r307-window-numbers-and-worker-auth.md`.

## R309: панель показывает и меняет горячие настройки реестра

**Живой пробел.** Балансер с R278 держит реестр «горячих» настроек (17 штук —
применяются без рестарта), и `GET /api/v1/settings` отдаёт готовый ответ «что
действует и откуда взято». Поиск `api/v1/settings` по `webui/**` давал **ноль
совпадений**: в панели были только старые поля `config.json` (требуют
перезапуска), а значения из env выглядели как «ни на что не влияет». Это ровно
жалоба оператора «всё, что задаётся в env, должно быть изменяемо из WebUI».

**Что сделано.** Секция «Горячие настройки (применяются без рестарта)» на странице
настроек: группировка по `group`, в строке — имя, описание с сервера, ДЕЙСТВУЮЩЕЕ
значение, бейдж источника (`по умолчанию` / `из env` / `задано в панели`), поле
ввода, «Применить» и «Сбросить» (активна только для override). Всё состояние
реестра живёт в одном модуле `webui/js/modules/settings-registry.js`; страница
отдаёт только контейнер, поэтому «правка в одном месте не лечит» здесь больше не
воспроизводится.

**Проверка живьём.**

| # | Проверка | Результат |
| --- | --- | --- |
| W1 | `PUT /api/v1/settings {"LB_DONOR_ALLOW_OWN_COPIES":1}` | `applied:"override", effective:1, source:"override"` |
| W2 | `GET /api/v1/settings` после записи | `effective=1 source=override default=0` |
| W3 | ПРИМЕНЕНИЕ в поведении | `GET /api/v1/backends` сразу: у донора `canLoadOwnModels=true` (до записи было `false`) — **PASS**: настройка применилась без рестарта |
| W4 | `POST /api/v1/settings/reset {"name":"LB_DONOR_ALLOW_OWN_COPIES"}` | `effective:0 source:"default"`, `overrides:0`, в бэкендах снова `canLoadOwnModels=false` — **PASS** |
| W5 | Живой payload → реальный модуль панели (node, без браузера) | 17 строк, 4 группы, 17 бейджей, описания с сервера, `effective` видно, 17 «Применить» + 17 «Сбросить», сводка по `sourcePriority` — **PASS** |
| W6 | Отдача новых файлов стендом (`:18083`) | `settings-registry.js` 200, `index.html` содержит секцию и `<script>`, i18n-ключи `settings.hot.*` на месте — **PASS** |
| W7 | Полный прогон webui-тестов | 82 файла, **0 провалов**; новый тест — 24 проверки |

**Не проверено:** клики в живом браузере (рендер проверен через node с настоящим
payload и сквозь тесты; сам браузер здесь недоступен).

Чего сознательно НЕ делали (этап 5): не сливали старые поля `config.json` с
реестром — это разные механизмы (первые требуют рестарта), и молчаливое
объединение снова смешало бы «дефолт загрузки» и «политику перезагрузки».

## R308 (попутно): тест очереди перестал мерить служебные GET

`TestLoadBalancing_SameClientQueueFIFO` падал на каждом прогоне («semaphore
breach!») и в том же прогоне печатал «✅ PASS: strict serial queue». Причина —
измерение: счётчик одновременных и sleep висели на ЛЮБОМ запросе к моку, включая
`GET /api/models` (проверка наличия модели) и `/api/models/load/progress`. Пик «6»
складывался из одного инференса и пяти одновременных проверок. Теперь мок отвечает
мгновенно на всё, кроме `POST /api/generate`, а проверка не ослаблена. Полный
прогон `internal/balancer` — **зелёный впервые** (был единственный предсуществующий
провал).

## R310: восстановление русских комментариев из истории git

**Живой факт.** В 10 Go-файлах русские комментарии превратились в `????`: массовый
коммит 2026-07-03 записал файлы через кодировку без кириллицы, каждый не-ASCII
символ стал одним `?`. Код не пострадал (там ASCII), потерялся только текст
комментариев — включая объяснения живых дефектов, из-за которых этот код и
переписывался.

**Метод (и почему не «в лоб»).** Исходный текст лежит в истории: у 8 из 10 файлов
есть блобы с кириллицей (2026-06-16…2026-07-03). Ключ строки строится
СИММЕТРИЧНО: в текущей строке участки `?` свёрнуты в ранги, в исторической — все
не-ASCII символы заменены на `?` (порча была 1:1 по символам). Матчинг идёт по
ВСЕМ историческим блобам файла, а не по одному коммиту: порча внесена раньше, чем
казалось (в `e196fd4f^` уже 447 `????` в `handlers_chat.go`). Отступ берётся из
текущей строки, окончания строк сохраняются.

**Результат: 539 строк восстановлено, 141 осталась** (см. отдельный список
`2026-10-30-r310-leftover-mojibake.md`).

**Проверка «код не тронут».** 540 пар «удалено/добавлено»: у всех, кроме одной,
совпадает часть строки до `//`; единственное исключение — клиентская строка в
`internal/balancer/nctx_reload.go`, где `?` заменён на `—` (найдено по блобу от
2026-06-27, где там стоит тире). Отдельно проверено: BOM нет, CRLF не появился
(в этих файлах его и не было), `go build`/`go vet` — 0, `cmd/cppworker` и
`internal/balancer` — зелёные.

**Что это даёт.** Вернулись объяснения дефектов, ради которых код переписывался:
например, в `inference.go` — почему `MaxVRAMNCtx` и `NCtxOverride` вместе
управляют отказом, в `handlers_model.go` — почему `max_vram_n_ctx=0` означает
«данных о VRAM нет» (R83), в `auto_tune_nctx.go` — живой пример с RTX 3070
(`required_n_ctx=53897`, `max_vram_n_ctx=32719`), из которого потом вырос R306.
