## 1. Что вошло в релиз

### WebUI: вход и роли
- Динамический upstream панели (`resolver 127.0.0.11`) — после `up -d` панель
  больше не отдаёт 503 из-за устаревшего IP балансера.
- Путь `users.json` объяснён и виден (`/app/data/users.json` на томе
  `balancer_data`); ошибка записи файла при создании администратора больше не
  глотается — WARN с подсказкой.
- Доктор `scripts/diagnose-webui-auth.ps1` (read-only) и
  [docs/features/webui-auth.ru.md](../features/webui-auth.ru.md) с разбором шести типовых причин.

### Профили, ленивая загрузка, отмена
- Ленивая загрузка применяет профиль модели (окно из профиля, а не env-дефолт),
  включая сценарий «кэш профилей пуст».
- Отмена генерации клиентом (`POST /api/cancel`) доходит от балансера до воркера
  (скоуп по модели), время остановки — десятки миллисекунд; при пустой отмене
  печатается диагностика раскладки (порт 50052, `/api/rpc-peers`).
- Недоступный донор на время работы с моделью **исключается**, а не роняет
  загрузку: TCP-фильтр на загрузке, `rpc_excluded` в `/api/models`, снимок
  инвалидируется по составу узлов.

### AutoTune (R230): корректная память и проверяемые рекомендации
- Единицы: МБ метрик больше не передаются как байты (было «свободно 0 GB»).
- Reload-бюджет: `free + occupancy` этой модели (перезагрузка её выгружает).
- `n_kv_heads`/`head_dim` добираются из `/api/show`; без них раскладка не меняется.
- KV выбирается по фактическому `n_ctx`; слои — по реально влезающему числу;
  `-2` больше не рекомендуется, уменьшение слоёв запрещено.
- Применение плана сверяется с фактом: «success» без изменения конфигурации
  невозможен; при ошибке — честный failure и cool-down.
- Табличные тесты на **144 конфигурации** (VRAM 8/16/24/32 GiB × RAM 16/32/64/120 GiB
  × 3 модели × 3 контекста) + живой сценарий A10 (24 ГБ, `ctx=131072`, KV q8_0).
  Живая проверка — `scripts/verify-autotune-r230.ps1`.

### Стрим для Cline (R231): без дублей, без маркеров, один `[DONE]`
- Размышления больше не копируются в `content` в стриме (`FinalizeForStream`);
  незакрытый блок даёт честный `finish_reason=length`, а не `stop` при пустом content.
- `</think>`, `<|channel>thought`, `<end_of_turn>` не попадают в видимый текст;
  лишние закрывающие маркеры вырезаются и в воркере, и на границе балансера.
- Фильтр SSE на балансере теперь реально работает (раньше получал голый JSON и был
  no-op) и не выбрасывает чанк целиком при очистке.
- Завершающий `[DONE]`/`done:true` отдаётся **всегда** и ровно один раз (раньше —
  только при включённом авто-продолжении, иначе поток завершался молча).
- Живая проверка — `node scripts/verify-stream-r231.js`; контракт клиентов
  (OpenAI + Ollama) — `scripts/clients/contract-suite.js` с новым блоком 6.

### RPC-раскладка: измеренный выигрыш
- На `Qwen3.8-27B-UD-Q4_K_M` (15.33 GiB, `ctx=16384`, KV q8_0) раскладка на донора
  даёт **≈2.9× по скорости генерации** (136 с → 46 с на 96 токенов), раскладка
  меняется с 20/66 слоёв на GPU до 48/66; загрузка почти не дорожает (+2.5 %).
- Методика и ограничения — [rpc-benchmark-qwen38.md](../features/rpc-benchmark-qwen38.ru.md);
  воспроизведение — `pwsh -File scripts/bench-rpc-qwen38.ps1 -Mode both`.

### Документация и инструменты
- Обновлены README (раздел производительности) и индекс документации.
- Новые/обновлённые документы: `rpc-benchmark-qwen38.md`,
  `rpc-layout-rules.md` (§10), `ENV_VARS.md` (`CPPWORKER_LOAD_STALL_SEC`),
  `troubleshooting.md` (AutoTune/стрим/большая загрузка),
  `cline-agent-loop.md` (стриминговый контракт R231).
- Новые проверки: `scripts/bench-rpc-qwen38.ps1`,
  `scripts/verify-stream-r231.js`, `scripts/verify-autotune-r230.ps1`,
  `scripts/verify-lazy-profile-cold-cache-r229.ps1`,
  `scripts/diagnose-webui-auth.ps1`.
- Гигиена репозитория: из индекса убраны `debug/` (дампы Cline-сессий, трейсы,
  env-снимок узла), персональные контакты в примерах заменены placeholder'ами.

## 2. Как проверялось

| Проверка | Результат |
|---|---|
| `scripts/ci.ps1 -Live -Clients` | **4/4 PASS** — unit (Go+JS), live regression, contract-suite (OpenAI+Ollama), WebUI auth/roles e2e |
| AutoTune | таблица 144 конфигураций + A10-сценарий; живьём: «бюджет 8.0 GB» вместо «0.0 GB», рекомендация f16 + все слои применилась и подтвердилась, повторных reload нет |
| Стрим Cline | 3/3 живых прогона: content не дублирует reasoning, маркеров нет, `[DONE]` один и последний; contract-suite блок 6 PASS |
| RPC | раскладка 48/66, 0.71 → 2.08 tok/s (≈×2.9), загрузка 278 → 285 с |
| Отмена генерации | остановка за 58–162 мс, на доноре `by:"model"` |

Артефакты живых прогонов лежат в `_diag/` (вне git): `ci-*.log`,
`bench-rpc-qwen38-result.json`.

## 3. Обновление с rc1

1. **Образы:** `balancer:r231-stream`, `cppworker:gpu-r231-stream`,
   `webui:r229m-authproxy`, `imageworker:cuda-75-86-120` (теги — в
   `deployments/.env`).
2. **Обязательно для моделей ≥ ~15 ГБ:** `CPPWORKER_LOAD_STALL_SEC=1200` в
   `deployments/.env` (дефолтные 300 с обрывают загрузку на медленном диске).
3. **Раскладка:** режим — `PUT /api/v1/backends/{id}/rpc-layout`
   `{"mode":"auto"|"on"|"off"}`; `auto` — рекомендация. Перед замером выигрыша
   проверьте канал (`POST .../measure-link`).
4. **AutoTune:** ничего включать не нужно (глобальный/per-model флаг как раньше);
   после обновления рекомендации считаются по фактической памяти.
5. **Клиенты:** перезапуск не требуется; для Cline/OpenWebUI стрим стал
   контрактным (маркеры/дубли/`[DONE]`).

## 4. Известные ограничения

- Ручной smoke на A10 из [v1.0-smoke-checklist.md](v1.0-smoke-checklist.ru.md) —
  по-прежнему ручной шаг перед финальным тегом.
- RPC-выигрыш зависит от канала и VRAM донора; на медленном канале возможен
  регресс — мерить, а не предполагать.
- Загрузка 15-ГБ модели на этом стенде занимает ~5 минут (диск), это не регресс
  кода; лечится `CPPWORKER_LOAD_STALL_SEC` и кэшем страниц ОС.
- Исторические записи CHANGELOG содержат внутренние адреса/имена прошлых стендов
  (история, не секреты); актуальные конфиги — только в `deployments/.env` (gitignored).
