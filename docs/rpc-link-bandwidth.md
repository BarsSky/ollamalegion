# Канал между узлами раскладки: как определяется и где задаётся (R166, 2026-10-17)

Документ отвечает на один вопрос: **какую пропускную способность считает балансер,
когда предлагает раскладку слоёв между хостами, и кто её определяет.**

## 1. Почему это ключевой параметр

При раскладке слоёв (`layer split`) каждый токен пересекает границу между машинами:
активации уходят на удалённый узел и возвращаются. По пропускной способности канала
считается:

* трафик на токен (`hidden_size × bytes` для layer; `× layers` для row);
* трафик на префилл (`prefill_tokens ×` то же);
* доля накладных расходов от времени токена (`tokenOverheadPercent`).

Формулы — `internal/composition/traffic.go`. Если занизить канал в 10 раз (например,
считать 1 Гбит/с на канале 10 Гбит/с), сухой прогон покажет «сеть не тянет» и
композиция будет отклонена зря.

## 2. Лестница источников (сверху вниз)

Резолвер — `internal/balancer/link_bandwidth_r166.go`, функция `LinkBandwidthInfo`.

| Приоритет | Источник (`source`) | Откуда берётся | Когда используется |
|---|---|---|---|
| 1 | `request` | тело запроса `bandwidthMBps` (**МБ/с**) | оператор задал значение в WebUI или через API |
| 2 | `auto` | **автозамер балансера**: скачивание 8 МиБ с `/api/rpc-link-probe` узла, Мбит/с | замер свежий (моложе 3 периодов), у узла роль `main`/`donor` |
| 3 | `env` | `LB_RPC_LINK_MBPS` (Мбит/с) | автозамера нет, но оператор положил число из `scripts/measure-network.ps1` |
| 4 | `default` | 112 МБ/с (1 Гбит/с, историческое значение §3) | ничего не измерено |

Важные свойства:

* **автозамер главнее `.env`**: он меряет тот же путь, которым идут слои
  (`cppworker ↔ cppworker`, контейнерная сеть), а `.env` — путь хост↔хост;
* при нескольких участниках берётся **самый медленный** канал: раскладка синхронна,
  общий темп задаёт он;
* **протухший замер не используется** (лучше честный `env`/`default`, чем старая
  цифра, выданная за измерение);
* узлы без роли `main`/`donor` не участвуют — у них нет `rpc-server`.

В ответе API (и в панели) всегда есть поле `bandwidth`:

```json
{"mbps": 1064, "mbps_bits": 8515, "source": "auto",
 "backendId": "cppworker-gpu-bundled-agent",
 "detail": "авто-замер балансера до узла … (путь cppworker↔cppworker, как у самих слоёв)"}
```

## 3. Автоопределение при инициализации

### Балансер

* `StartRPCLinkMeasurer` (`internal/balancer/rpc_link_measure_r118.go`) запускается при
  старте: **первый замер через 30 с** (узлы успевают зарегистрироваться), далее раз в
  `LB_RPC_LINK_MEASURE_SEC` (по умолчанию 900 с; `0` — выключить).
* Замер идёт только до узлов с ролью `main`/`donor`.
* Неудачный замер **не затирает** предыдущую успешную цифру.

### Бэкенд (cppworker)

`/api/info` отдаёт блок `net` (R166, `cmd/cppworker/netlink_r166.go`):

```json
"net": {"interface": "eth0", "mtu": 1500, "source": "detected",
        "note": "MTU 1500: jumbo не включён — возможна фрагментация на больших пакетах"}
```

Это **обнаружение, а не измерение**: в контейнере интерфейс обычно `veth`, и его
`speed` из `/sys` либо отсутствует, либо равен скорости хостового линка. Поэтому поле
помечено `source=detected` и не подменяет замер балансера. В панели эти числа разные
по смыслу, и путать их нельзя.

## 4. Где задать в WebUI

Страница **«Бэкенды» → «Объединение бэкендов»**, блок **«Канал между узлами»**:

* поле **Мбит/с** — явное значение оператора (сохраняется в браузере);
* **пустое поле = «авто»**: балансер сам подставит свой замер;
* кнопка **«Замерить»** — POST `/api/v1/rpc/link/measure`, замер сейчас;
* подсказка под полем показывает, что реально ушло в оценку трафика и с каким
  источником: «в оценке трафика: 8515 Мбит/с (1064 МБ/с), источник: автозамер
  балансера».

## 5. API

| Метод и путь | Назначение |
|---|---|
| `POST /api/v1/rpc/link/measure` | замерить сейчас. Тело `{}` — все участники раскладки; `{"backendId": "..."}` — один узел. Ответ: `results[]` (по узлам) + `effective` |
| `POST /api/v1/placement/validate` | сухой прогон композиции; принимает `bandwidthMBps` (МБ/с), возвращает `bandwidth` с источником |
| `POST /api/v1/placement/plan` | предлагаемый план; тоже принимает `bandwidthMBps` и возвращает `bandwidth` |
| `GET /api/v1/backends` | в записи бэкенда: `rpcLink` (замер оператора из `.env`) и `rpcLinkAuto` (замер балансера) — **раздельно и с источниками** |
| `GET /api/info` (воркер) | блок `net`: интерфейс, MTU, скорость линка (если ядро отдаёт) |

## 6. Конфигурация

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `LB_RPC_LINK_MEASURE_SEC` | период автозамера, `0` — выключить | `900` |
| `LB_RPC_LINK_MBPS` | операторский замер (**Мбит/с**), fallback | пусто |
| `LB_RPC_LINK_MEASURED_AT`, `LB_RPC_LINK_SOURCE` | подпись к операторскому замеру | пусто |

Замеряемый объём — 8 МиБ на узел (`rpcLinkProbeBytes`). Обработчик `/api/rpc-link-probe`
разрешает 64 КиБ…64 МиБ.

## 7. Ориентиры: что даёт быстрый канал

Для модели класса 180B MoE (Qwen3.8-Flash-Next, 48 слоёв, поток 10 240 из-за
hyper-connections):

| Величина | 1 Гбит/с | 10 Гбит/с |
|---|---|---|
| Передача 24 ГБ весов на удалённую карту | ~3.6 мин | ~22 с |
| Накладные расходы на токен (layer) | 183 мкс | 19 мкс |
| Префилл 512 токенов | 94 мс | 10 мс |

То есть на 10 Гбит/с сеть перестаёт быть узким местом; остаются память (веса/KV) и
VRAM карт. Подробный расчёт под две A10 — `plans/2026-10-17-qwen38-flash-next-a10.md`.

## 8. Если что-то не так

| Симптом | Причина | Что делать |
|---|---|---|
| `409 нет узлов раскладки` при `/rpc/link/measure` | ни у одного бэкенда нет роли `main`/`donor` | назначить роли (WebUI → «Объединение бэкендов», или `PUT /api/v1/backends/{id}/role`) |
| `source: default` в ответе | автозамер не проходил, `LB_RPC_LINK_MBPS` пуст | нажать «Замерить»; проверить, что у узла отвечает `/api/rpc-link-probe` (образ cppworker r118-probe1+) |
| Автозамер заметно меньше хостового | замер балансера идёт через контейнерные сети Docker Desktop (NAT/WSL2) | это ожидаемо: слои идут тем же путём, ориентироваться на автозамер, а не на хост↔хост |
| Замер «протухает» (падает в `env`/`default`) | фильтр свежести: старше 3 периодов не используется | уменьшить `LB_RPC_LINK_MEASURE_SEC` или нажать «Замерить» |
| MTU 1500 при 10 Гбит/с | jumbo не включён | включить jumbo (9000) на обоих концах и коммутаторе; проверить `ping -f -l 8972` |
