**Дата:** 2026-11-10 · **Тип:** исходники + образ балансера
**Образы:** balancer `r261110-0737` (коммит — в `deployments/release-manifest.json`);

## 1. Зачем

R459 запретил уводить живую сессию на копию с меньшим окном. Запрет оказался
шире дефекта: «нужное окно» всегда равнялось окну сессии, поэтому короткий
запрос никогда не уезжал с занятой «широкой» копии на свободную. Плюс три
обходных пути (занятый слот, 503, failover) и единая очередь этот запрет вообще
не применяли, а «холодный кандидат» определялся по метрике без срока годности —
переезды стояли, пока поллер не обновит данные (~30 с).

## 2. Политика: вариант C (выбран 2026-11-09)

```
need = max(потребность запроса + резерв,
           окно АКТИВНОЙ сессии, если она активна в пределах TTL)
```

- Активная сессия держит широкую копию — короткий запрос её не уводит (это и
  есть защита R459: контекст не «переезжает» на урезанное окно).
- Сессия простояла дольше TTL — её окно больше не требование, переезд решает
  потребность конкретного запроса.

| Ручка | Умолчание | Смысл |
|---|---|---|
| `LB_R459_REQUEST_NEED` | `on` | учитывать потребность запроса; `off` — поведение R459 |
| `LB_R459_NEED_RESERVE` | `4096` | резерв к промпту, токены; `0` — ровно промпт |
| `LB_R459_SESSION_TTL_SEC` | `900` | сколько сессия активна; `0` — окно сессии всегда |
| `LB_R459_COLD_TTL_SEC` | `90` | срок годности метрики окна; `0` — всегда «точно» |

Второй переезд НЕ блокируется. При варианте C активная сессия не переезжает,
а «вернуть» её на широкую копию нужно именно тогда, когда запрос реально
требует больше окна — блокировка превратила бы медленный ход в 413.

- Полный `./internal/balancer/` — см. отчёт прогона (168+ с, зелёный).
- Новые тесты:
  - `session_move_need_r480_test.go` — активная сессия держит окно; остывшая
    использует потребность запроса; TTL=0 = поведение R459; ручки реально

    устаревшая/никогда не опрошенная = «неизвестно» (допуск с WARN); TTL=0.

    предикат; очередь не берёт отклонённый бэкенд и ждёт (таймаут), а не едет;
    `gate == nil` сохраняет прежний путь для новых сессий.
  - `queue_rejections_r480_test.go` — `window_too_small` с числами в
    `why_queued`; без контекста переезда причина не появляется.
- Сторожевые тесты проекта обновлены/пройдены: `TestR387_STEWARD_EverySwitchIsDocumented`
  (четыре новые ручки описаны в `feature-switches.ru.md`),
  `TestR301_StewardNoStreamingBypass` (guard по-прежнему до очереди),

покрыта тестами с двумя бэкендами; живая проверка требует второго узла.
