# OllamaLegion v0.7.231 — заметки о релизе

Релиз исходников после R246. Закрывает тему «клиенты и агенты, которые раньше не
работали»: Anthropic `/v1/messages`, OpenAI `/v1/responses`, `strict:true` как
проверяемая схема, повтор генерации при невалидных аргументах и vision без
молчаливого отбрасывания. План и журнал:
`docs/plans/2026-10-26-clients-agents-contract-r247.md`.

## Что не работало

| Класс клиента | Что было |
|---|---|
| Anthropic-native (Claude Code, `anthropic` SDK) | `POST /v1/messages` → 404, клиент бесполезен |
| Codex-style / Responses API | `POST /v1/responses` → 404 |
| Structured output (`strict:true`) | поле принималось, но схема не проверялась |
| Слабые модели при жёстких схемах | невалидные аргументы уходили клиенту → ошибка инструмента, потерянный ход |
| Мультимодальные клиенты | картинки **молча** вырезались: 200, будто модель видела изображение |

## Что сделано

**Этап A/F — strict и повтор генерации.**
`tool_schema_validate_r247.go`: проверка аргументов по объявленной JSON-схеме
(`type` включая `integer`/`number` и type-массив, `required`, `enum`, `const`,
`items`, `properties`, `additionalProperties`, `anyOf/oneOf`). Проверяются только
инструменты `strict:true` (из `tools[].function.strict` или из самой схемы). При
нарушениях — один повтор генерации; на `/v1` повтор идёт с **nudge** (перечень
нарушений в system), на `/api/chat` — повтор тем же промптом. Выключатель
`CPPWORKER_STRICT_ARGS_RETRY=0`.

**Этап B — Anthropic Messages API.**
`POST /v1/messages` и `/v1/messages/count_tokens`. Трансляция в обе стороны поверх
собственной `/v1/chat/completions` (self-proxy), поэтому Anthropic-клиент получает
весь уже работающий слой: ремонт аргументов, strict, tool-историю по шаблону
модели, повторы, admission, сессии. Блоки `text/image/tool_use/tool_result`,
`input_schema`→`parameters`, `tool_choice` auto/any/tool; ответ — блоки
`text`/`tool_use` (`input` — объект), `stop_reason`, `usage`; SSE в порядке
Anthropic (`message_start` … `input_json_delta` … `message_stop`); ошибки в форме
Anthropic. `count_tokens` отдаёт консервативную оценку вместо 404.

**Этап C — OpenAI Responses API.**
`POST /v1/responses` по той же схеме. `input` строкой или items (`message`,
`function_call`, `function_call_output`), `instructions`→system, плоские `tools[]`
(+`strict`), `max_output_tokens`; ответ — `{object:"response", output[],
output_text, usage}` с items `message`/`function_call`; события `response.created` …
`response.completed` с `sequence_number`. `previous_response_id` — честный 400.

**Этап D — vision без тихой лжи.**
Части-картинки (`image_url`, Anthropic `image`, Responses `input_image`) больше не
вырезаются молча: HTTP 415 + `X-Vision-Supported: false`, `X-Vision-Parts: N`,
`error.code = vision_not_supported`. Проверка стоит ДО нормализации. Проводка
mmproj остаётся отдельным проектом — контракт отказа зафиксирован тестами.

**Этап E — контур ожиданий клиентов.**
`scripts/webui-e2e/client-expectations-r247.js` — профили-декларации «что клиент
считает правильным ответом» (поля/типы, порядок и терминаторы, запреты, второй ход
с результатом инструмента): Cline, Roo, DSH, OpenWebUI (×2), Continue/LangChain
strict, forced tool_choice, legacy functions, Anthropic (×2), Responses (×2),
vision-honest, strict-loop.

## Известные ограничения

- `input_tokens` в `message_start` Anthropic отправляется как `0` (usage приходит
  в `message_delta`); `thinking`-блоки с `signature` и `cache_control` не
  транслируются.
- Vision: честный отказ; картинки в модель не проводятся (нужен mmproj-путь).
- `previous_response_id` не поддерживается (состояние диалога не хранится).
- Качество вызова инструмента остаётся свойством модели; слой гарантирует форму,
  ремонт аргументов и повтор, а не «ум» модели.
